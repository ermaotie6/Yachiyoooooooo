## 核心管线（端到端）

### 一次用户弹幕的完整流程

```
用户发送 "你好八千代！"
  │
  ▼
┌─ 前端 LiveStream.vue ─────────────────────────────────────────────┐
│ 1. ChatPanel 输入框 → useWebSocket.sendUserMessage(content)        │
│ 2. WebSocket → ws://backend:9001                                   │
└───────────────────────────────────────────────────────────────────┘
  │  user_message JSON
  ▼
┌─ 后端 WebSocketMessageHandler ────────────────────────────────────┐
│ 1. authenticateAndGetUserId()  — JWT 令牌验证                      │
│ 2. moderateAndPersist()         — 6层内容审查 + 数据库持久化        │
│ 3. broadcastUserMessage()       — 广播消息给所有在线观众            │
│ 4. processAvatarPipeline()      — 调用 Avatar 响应管线              │
└───────────────────────────────────────────────────────────────────┘
  │
  ▼
┌─ AvatarResponseService (管线编排) ────────────────────────────────┐
│                                                                   │
│  [步骤 1] DeepSeekModerationService.moderate()                    │
│    内容合法性二次判断 → pass / review / block                      │
│    block → 管线终止，返回 "内容不当"                                │
│                                                                   │
│  [步骤 2] OpenClawGateway.processMessage()                        │
│    POST OpenClaw /v1/chat/completions                             │
│    System Prompt: yachiyo_system_prompt.txt (要求 JSON 输出)      │
│    → 返回: {"text":"中文回复","emotion":"happy","action":"wave",  │
│             "translation":"日语翻译"}                              │
│    容错: JSON parse → 成功; 失败 → 文本标签 fallback              │
│    重试: 最多 2 次, 退避 1s/3s                                    │
│    熔断: 3 次连续失败 → 30s 短路                                   │
│                                                                   │
│  [步骤 3] TranslationService.translate()                          │
│    优先: 使用 OpenClaw 返回的 translation 字段 (已内嵌)            │
│    Fallback: 百度翻译 API → DeepSeek LLM 翻译 → 原文               │
│    目标语言: ja (日语)                                             │
│                                                                   │
│  [步骤 4] GPTSoVITSService.synthesizeWithEmotion()                │
│    文本: 日语翻译文本                                              │
│    情感: happy → 参考音频 yachiyo_happy.wav                        │
│    POST GPT-SoVITS /synthesize → audio_url + duration_ms          │
│    失败 → audio_url=""  (静默降级)                                 │
│                                                                   │
│  [步骤 5] Live2DAnimationService.generateAnimationSequence()      │
│    emotions: ["happy"] → 表情 f_smile                              │
│    actions: ["wave"]   → 动作 m_wave                              │
│    → animation_commands: [expression, motion]                     │
│                                                                   │
│  [步骤 6] 组装 AvatarResponse JSON                                │
│    {text, original_text, emotions, actions,                       │
│     audio_url, audio_duration_ms, animation_commands}             │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
  │  AvatarResponse JSON
  ▼
┌─ 后端 WebSocketService ──────────────────────────────────────────┐
│ sendToClient(clientId, response)          — 发给发送者             │
│ broadcast 给其他观众 (跳过发送者)           — 同步给所有观众        │
└───────────────────────────────────────────────────────────────────┘
  │  WebSocket → avatar_response
  ▼
┌─ 前端 LiveStream.vue ─────────────────────────────────────────────┐
│ 1. chat.addAvatarResponse() → 添加到消息列表                       │
│ 2. subtitle.startProgressive() → 字幕逐字显示                     │
│ 3. AvatarStage.playAnimations() → Live2D 表情+动作                │
│ 4. audio.play(audioUrl) → Web Audio API 播放语音                  │
│ 5. AnalyserNode → mouthOpenY → 驱动嘴部动画                        │
│ 6. 音频结束 → 嘴部闭合, 表情恢复 f_smile, 字幕清除                 │
└───────────────────────────────────────────────────────────────────┘
```

## OpenClaw 对接架构

### 为什么是直连而非桥接

旧版通过 `bridge/`（Node.js Express 代理）中转。审计发现 bridge 是死代码，C++ 后端早就在直连 OpenClaw。因此移除桥接层，简化链路：

```
旧: C++ → Bridge (Node.js :8765) → OpenClaw (:8000)
新: C++ → OpenClaw Gateway (:8100) /v1/chat/completions
```

### OpenClawGateway v2 设计

```
processMessage(userId, text)
  │
  ├── 缓存命中? → 返回缓存 (TTL 300s)
  │
  ├── sendWithRetry(message)
  │     ├── 熔断检查 — 连续 3 次失败 → 快速返回错误
  │     ├── attempt 1: sendToOpenClaw()
  │     ├── 失败 + 可重试?
  │     │     ├── 4xx → 不重试 (客户端错误)
  │     │     ├── 5xx/网络 → sleep(1s) → attempt 2
  │     │     └── 仍失败 → sleep(3s) → attempt 3
  │     └── 记录结果 (熔断计数)
  │
  └── 解析响应
        ├── parseJsonResponse()  ← 主路径
        │     尝试 json::parse(content)
        │     检查: text, emotion, action, translation 字段
        │
        └── parseTaggedResponse() ← Fallback
              正则: [emotion:xxx], [action:xxx], [translated]
```

### System Prompt 格式

新版 System Prompt (`backend/config/yachiyo_system_prompt.txt`) 要求 OpenClaw 返回纯 JSON：

```json
{"text":"你好呀神明大人！","emotion":"happy","action":"wave","translation":"こんにちは神様！"}
```

旧版文本标签格式 (`[emotion:happy]\n...`) 作为 fallback 仍然支持。

## 管线容错与降级

每个外部服务独立容错——单点失败不影响其他步骤：

| 服务 | 不可用时 | 影响 |
|------|---------|------|
| OpenClaw | 重试 2 次, 熔断 30s | 管线中断（AI 回复是核心依赖） |
| 百度翻译 | 自动切换到 DeepSeek LLM 翻译 | 翻译速度稍慢 |
| 所有翻译 | 返回中文原文 | 语音可能是中文（日语模型效果差） |
| GPT-SoVITS | audio_url="" | 只有文字+动画，无语音 |
| DeepSeek 审核 | 回退到本地规则审核 | 审核精度降低 |
| Redis | 跳过缓存和速率限制 | 无缓存，无速率保护 |

## WebSocket 通信协议

| 消息类型 | 方向 | 触发时机 |
|---------|------|---------|
| `identify` | 前端→后端 | 连接建立后，关联 userId |
| `user_message` | 前端→后端 | 用户发送弹幕 |
| `user_broadcast` | 后端→前端 | 审核通过后，广播给所有观众 |
| `avatar_response` | 后端→前端 | AI 管线完成，推送文本+音频+动画 |
| `status` | 后端→前端 | 管线进度通知 |
| `error` | 后端→前端 | 错误信息 |
| `ping`/`pong` | 双向 | 30s 心跳 |

### 消息格式

**user_message** (前端→后端):
```json
{
  "type": "user_message",
  "data": {
    "content": "你好八千代！",
    "user_id": "123",
    "username": "ermaotie",
    "access_token": "***",
    "language": "ja"
  }
}
```

**avatar_response** (后端→前端):
```json
{
  "type": "avatar_response",
  "data": {
    "request_id": "resp_1234567890",
    "text": "こんにちは神様！",
    "original_text": "你好呀神明大人！",
    "emotions": ["happy"],
    "actions": ["wave"],
    "audio_url": "http://gpt-sovits:5000/audio/output_xxx.wav",
    "audio_duration_ms": 2800,
    "animation_commands": [
      {"type": "expression", "params": {"expression_name": "f_smile", "duration_ms": 2000}},
      {"type": "motion", "params": {"group": "TapBody", "index": 1, "priority": 1}}
    ],
    "processing_time_ms": 2525
  }
}
```

## 启动流程

### 后端启动顺序

```
1. parseArguments()          → 解析 --config-dir / --env / --port
2. ConfigManager::init()     → 加载 config.yaml
3. LogUtils::init()          → spdlog 日志系统
4. initializeHttpServer()    → Crow HTTP/WS 框架
5. initializeDatabase()      → PostgreSQL 连接池
6. initializeAIServices()    → AI 提供商检测
7. initializeServices()      → ServiceRegistry.buildPipeline()
   ├ WebSocket (:9001)
   ├ Redis
   ├ ServiceRegistry: OpenClaw → 翻译 → TTS → 动画 → 审核 → AvatarService
   ├ WebSocketMessageHandler: 注册 WS 回调
8. initializeControllers()   → 注册 REST 路由
9. start()                   → 启动 HTTP 服务器
```

### 前端启动顺序

```
1. Pinia auth store 初始化
2. 从 localStorage 恢复 token + user
3. 验证 token 有效性 (GET /api/v1/auth/me)
4. 路由守卫检查认证状态
5. LiveStream: useWebSocket.connect(userId)
6. 注册 WS 事件回调 (onAvatar, onBroadcast, onError)
```

## 6 层内容审核

每条用户消息依次通过 6 层安全检查：

| 层 | 名称 | 实现 | 失败处理 |
|----|------|------|---------|
| 1 | 速率限制 | Redis 计数器 (10条/分钟) | REJECTED |
| 2 | IP 黑名单 | DB 查询 | REJECTED |
| 3 | 关键词过滤 | 敏感词库匹配 | MANUAL_REVIEW |
| 4 | AI 语义审核 | DeepSeek API | API 不可用→规则 fallback |
| 5 | 行为分析 | 频率/IP/拒绝率 | 异常→标记 |
| 6 | 综合评分 | 加权计算 spamScore | ≥0.6→REJECTED, ≥0.3→REVIEW |

审核通过后消息持久化到 PostgreSQL `user_messages` 表。

## 端到端时间线

以 "你好，八千代！" 为例：

```
T+0ms      用户按下 "发送"
T+2ms      WebSocket → 后端 :9001
T+5ms      WebSocketMessageHandler 开始处理
T+10ms     6层审核 → pass
T+15ms     广播 user_broadcast
T+50ms     OpenClawGateway.sendWithRetry() 开始
T+800ms    OpenClaw 返回 JSON 响应
T+810ms    翻译步骤 (使用 OpenClaw 内置 translation 字段, 跳过 API 调用)
T+820ms    GPT-SoVITS /synthesize (CPU 模式 ~5-15s, GPU ~0.5-2s)
T+2500ms   TTS 完成 → audio_url
T+2510ms   Live2D 动画指令生成
T+2520ms   组装 AvatarResponse
T+2525ms   WebSocket 推送
T+2530ms   前端收到 → 显示文本 + 字幕 + 动画 + 播放语音
T+5300ms   语音播放完毕 → 嘴部闭合, 字幕清除, 表情恢复
```

**端到端延迟**: ~2.5s（主要瓶颈: GPT-SoVITS TTS ~1.7s）
