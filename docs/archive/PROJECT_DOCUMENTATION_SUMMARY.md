## 📖 快速开始指南

### 1. 本地开发环境

```bash
# 启动开发环境
./start_dev_environment.sh

# 访问地址
# 前端:      http://localhost
# API:       http://localhost:8080
# Grafana:   http://localhost:3000
```

### 2. 编译后端

```bash
cd backend
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . -- -j$(nproc)
./bin/yachiyo_backend
```

### 3. 构建前端

```bash
cd frontend
npm install
npm run build
# 输出在 dist/ 目录
```

### 4. Docker 部署

```bash
# 构建镜像
docker-compose build

# 启动服务
docker-compose up -d

# 查看日志
docker-compose logs -f
```

### 5. Kubernetes 部署

```bash
# 创建命名空间和资源
kubectl apply -f k8s/

# 检查状态
kubectl get pods -n yachiyo
kubectl get svc -n yachiyo

# 查看日志
kubectl logs -n yachiyo -l app=yachiyo-backend
```

## 🛠️ 常见问题

### Q: 如何更新代码？

A: 使用以下流程：
1. 在 `develop` 分支进行开发
2. 提交 PR 并通过 CI/CD 检查
3. 合并到 `develop`，部署到测试环境
4. 验证无误后，合并到 `main`，部署到生产

### Q: 如何处理性能问题？

A: 按优先级处理：
1. 检查监控指标定位问题
2. 查看日志分析根本原因
3. 执行优化（参考 PERFORMANCE_OPTIMIZATION_GUIDE.md）
4. 在测试环境验证
5. 灰度部署到生产

### Q: 如何扩展系统？

A: 遵循以下步骤：
1. 水平扩展（添加服务器）
   - 增加后端副本数
   - 配置负载均衡
   - 配置自动扩展 (HPA)
2. 数据库扩展
   - 读副本 (Replication)
   - 分片 (Sharding)
   - 连接池优化
3. 缓存优化
   - Redis 集群
   - 缓存预热
   - TTL 调整

### Q: 发生生产事故怎么办？

A: 按照应急流程：
1. **立即行动** (< 1 分钟)
   - 激活告警
   - 通知值班团队
   - 初步诊断

2. **快速恢复** (1-5 分钟)
   - 执行自动回滚
   - 或手动切换到备份版本
   - 验证服务恢复

3. **沟通** (5-15 分钟)
   - 更新状态页面
   - 通知用户
   - 通知利益相关方

4. **调查** (后续)
   - 收集日志和指标
   - 分析根本原因
   - 制定改进措施
   - 进行事后分析
