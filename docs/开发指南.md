## 开发环境搭建

### 前置软件

| 软件 | 最低版本 | 用途 |
|------|---------|------|
| Git | 2.x | 版本控制 |
| Docker + Docker Compose | 20.10+ / v2 | 运行数据库和其他基础设施 |
| CMake | 3.20+ | C++ 后端构建 |
| GCC 或 Clang | GCC 12+ / Clang 15+ | C++20 编译器 |
| Node.js | 18+ | 前端和桥接服务 |
| npm | 9+ | 包管理 |

### 系统依赖安装

#### Arch Linux

```bash
sudo pacman -S base-devel cmake ninja gcc git \
    openssl yaml-cpp postgresql-libs hiredis curl \
    nlohmann-json nodejs npm docker docker-compose
```

#### Debian / Ubuntu

```bash
sudo apt-get install -y build-essential cmake ninja-build gcc g++ git \
    libssl-dev libyaml-cpp-dev libpq-dev libhiredis-dev libcurl4-openssl-dev \
    nlohmann-json3-dev pkg-config nodejs npm
```

#### Windows (WSL2 推荐)

建议在 WSL2 中进行后端开发。前端和桥接服务可在 Windows 原生环境开发。

### 项目克隆

```bash
git clone https://github.com/ermaotie6/yachiyoooooooo.git
cd yachiyoooooooo
```

### 启动基础设施（数据库 + Redis）

开发时只需启动 PostgreSQL 和 Redis：

```bash
docker compose up -d postgres redis
```

验证数据库就绪：

```bash
docker compose exec postgres pg_isready -U postgres
# 期望: /var/run/postgresql:5432 - accepting connections
```

## 代码架构概述

### 设计模式

| 模式 | 使用位置 | 说明 |
|------|---------|------|
| 单例模式 | `Application`, `ConfigManager` | 全局唯一实例 |
| 服务层模式 | `AuthService`, `MessageService`, `AIService` | 业务逻辑封装 |
| 接口+实现 | `AuthService` / `AuthServiceImpl` | 面向接口编程 |
| DTO 模式 | `AuthDTO`, `ChatRequest`, `OpenClawDTO` | 数据传输解耦 |
| 管线模式 | `AvatarResponseService` | 7 步编排管线 |
| 网关模式 | `OpenClawGateway` | 外部服务抽象 |
| 观察者模式 | `WebSocketService` | 消息广播 |

### 命名空间

项目使用 `Yachiyo` 命名空间（首字母大写），历史遗留有部分 `yachiyo`（全小写），通过 `Compat.hpp` 中的 `namespace` 别名桥接：

```cpp
namespace Yachiyo {
    // 所有新代码放在这里
}

// Compat.hpp
namespace yachiyo = Yachiyo;
```

### 依赖关系图

```
Controllers
    │
    ├── AuthController → AuthServiceImpl → DatabaseService + JwtUtil + HashUtil
    ├── AIController → AIServiceImpl
    ├── UserController → DatabaseService
    ├── MessageController → MessageServiceImpl → DatabaseService + WebSocketService
    └── WebSocketController → AvatarResponseService
                                    │
                                    ├── OpenClawGateway → Bridge → OpenClaw
                                    ├── GPTSoVITSService (TTS)
                                    └── Live2DAnimationService (动画)
```

## 后端开发

### 编译

```bash
cd backend
mkdir -p build && cd build

# Debug 模式（开发推荐）
cmake .. -G "Ninja" -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_STANDARD=20
ninja

# Release 模式（部署用）
cmake .. -G "Ninja" -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_STANDARD=20
ninja
```

### 运行

```bash
./yachiyo_cpp --config-dir ../config --env dev --port 8080 --host 0.0.0.0
```

命令行参数：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--config-dir` | 配置文件目录 | `config` |
| `--env` | 运行环境 | `dev` |
| `--port` | HTTP 端口 | `8080` |
| `--host` | 监听地址 | `0.0.0.0` |
| `--workers` | 工作线程数 | CPU 核心数 |

### 添加新的 Controller

1. 在 `include/controllers/` 创建 `NewController.hpp`
2. 在 `src/controllers/` 创建 `NewController.cpp`
3. 在 `Application.cpp` 的 `initializeControllers()` 中注册
4. 在 `src/controllers/CMakeLists.txt` 中添加源文件

```cpp
// include/controllers/NewController.hpp
#pragma once
#include "controllers/BaseController.hpp"

namespace Yachiyo {
class NewController : public BaseController {
public:
    void registerRoutes(crow::SimpleApp& app) override;
private:
    void handleGet(const crow::request& req, crow::response& res);
};
}
```

### 添加新的 Service

1. 在 `include/services/` 创建接口头文件
2. 在 `include/services/` 创建实现头文件
3. 在 `src/services/` 创建实现源文件
4. 在需要使用的地方注入依赖

### ConfigManager 使用

```cpp
auto& config = ConfigManager::getInstance();

// 获取字符串
std::string host = config.getString("database.host", "localhost");

// 获取整数
int port = config.getInt("database.port", 5432);

// 获取布尔值
bool enabled = config.getBool("redis.enabled", false);

// 获取 YAML 数组元素 (通过数字索引)
std::string appid = config.getString("translation.services.0.appid", "");
```

> **注意**: ConfigManager 支持 dot-separated key path 和 YAML 数组索引。`translation.services.0.appid` 会自动识别 `services` 为数组，并取第 0 个元素的 `appid` 字段。

## 前端开发

### 安装和启动

```bash
cd frontend
npm install
npm run dev     # 开发服务器 http://localhost:5173
```

### 目录约定

| 目录 | 说明 | 示例 |
|------|------|------|
| `views/` | 路由页面组件 | `LiveStream.vue`, `Chat.vue` |
| `components/` | 可复用组件 | `Live2DComponent.vue`, `LoginDialog.vue` |
| `composables/` | 组合式函数 | `useWebSocket.ts`, `useAudioPlayer.ts` |
| `stores/` | Pinia 状态管理 | `auth.ts` |
| `api/` | API 客户端 | `client.ts` |
| `types/` | TypeScript 类型定义 | `index.ts` |
| `styles/` | 全局样式 | - |

### Axios Token 拦截器

`api/client.ts` 中配置了自动 Token 管理：

- **请求拦截器**: 自动添加 `Authorization: Bearer <token>` 头
- **响应拦截器**: 检测 401 → 自动调用 `/auth/refresh` → 重试原始请求
- **Token 刷新去重**: 多个并发 401 请求只触发一次 refresh

### Live2D 开发模式资源代理

`vite.config.ts` 中配置了 `serve-live2d-resources` 自定义插件：

- 开发时 `/resources/live2d/*` 请求自动代理到项目根目录的 `resources/live2d/` 文件夹
- 无需手动复制模型文件到 `frontend/public/`
- 生产构建时需要确保 Live2D 文件可通过静态服务器访问

### 添加新页面

1. 在 `views/` 创建 Vue 组件
2. 在 `router/index.ts` 注册路由
3. 如需认证，添加 `meta: { requiresAuth: true }`

## 桥接服务开发

桥接服务是一个极简的 Node.js HTTP 转发代理：

```bash
npm install
# 设置环境变量
export OPENCLAW_ENDPOINT=http://localhost:8000
node src/index.js
```

### 核心逻辑

`src/index.js` 只有一个关键端点：

- `POST /process` — 接收 C++ 后端的 JSON → 转发到 OpenClaw → 同步返回结果
- `GET /health` — 健康检查

### 环境变量

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `OPENCLAW_ENDPOINT` | OpenClaw 服务地址 | `http://localhost:8000` |
| `OPENCLAW_API_KEY` | OpenClaw 认证密钥 | 空 |
| `REQUEST_TIMEOUT_MS` | 请求超时 (毫秒) | `30000` |

## 配置管理

### 双配置文件策略

| 文件 | 环境 | 数据库 Host 默认值 |
|------|------|-------------------|
| `config/config.yaml` | 本地开发 | `localhost` |
| `backend/config/config.yaml` | Docker 部署 | `${DB_HOST:localhost}` |

### 环境变量注入

配置文件支持 `${ENV_VAR:default}` 语法：

```yaml
database:
  host: "${DB_HOST:localhost}"       # 读取 DB_HOST，不存在则用 localhost
  password: "${DB_PASSWORD}"         # 必须通过环境变量提供
```

Docker Compose 中通过 `environment` 段注入：

```yaml
backend:
  environment:
    - DB_HOST=postgres
    - DB_PASSWORD=postgres
    - REDIS_HOST=redis
    - JWT_SECRET_KEY=${JWT_SECRET_KEY}
```

## 调试技巧

### 后端调试

1. **日志级别**: 在 `config.yaml` 中设置 `server.log_level: "debug"` 查看详细日志
2. **GDB 调试**: Debug 构建后使用 `gdb ./yachiyo_cpp` 调试
3. **API 测试**: 使用 curl 或 Postman 直接调用 API

```bash
# 健康检查
curl http://localhost:8080/api/v1/health

# 注册用户
curl -X POST http://localhost:8080/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"test","email":"test@test.com","password":"Test1234"}'

# 登录
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"test","password":"Test1234"}'
```

### WebSocket 调试

使用浏览器开发者工具的 Network → WS 标签页查看 WebSocket 消息，或使用 `wscat`：

```bash
npx wscat -c ws://localhost:9001
# 连接后发送 identify 消息
> {"type":"identify","data":{"userId":"test123"}}
```

### 数据库调试

```bash
# 进入 PostgreSQL 容器
docker compose exec postgres psql -U postgres -d yachiyo

# 常用查询
SELECT * FROM users LIMIT 10;
SELECT * FROM messages ORDER BY created_at DESC LIMIT 10;
SELECT * FROM sessions WHERE user_id = 1;
```

### Redis 调试

```bash
# 进入 Redis 容器
docker compose exec redis redis-cli

# 查看所有 key
KEYS *

# 查看速率限制
GET rate_limit:user123
```

## 代码规范

### C++ 代码规范

- 使用 C++20 标准
- 头文件使用 `#pragma once`
- 命名空间：`Yachiyo::`
- 类名：PascalCase（如 `AuthServiceImpl`）
- 方法名：camelCase（如 `registerUser`）
- 成员变量：camelCase 或带 `m_` 前缀
- 常量：UPPER_SNAKE_CASE
- 文件名：PascalCase（头文件 `.hpp`，源文件 `.cpp`）

### TypeScript/Vue 代码规范

- 使用 Composition API（`<script setup lang="ts">`）
- 组件名：PascalCase（如 `LiveStream.vue`）
- composable 函数：`use` 前缀（如 `useWebSocket`）
- 类型定义集中在 `types/index.ts`
- 使用 Element Plus 组件库

## 常见开发场景

### 添加新的 AI 服务提供商

1. 在 `include/services/` 添加服务接口
2. 在 `Application.cpp` 的 `initializeAIServices()` 中注册
3. 在 `config.yaml` 中添加配置段

### 添加新的 Live2D 表情

1. 使用 Live2D Cubism Editor 导出 `.exp3.json` 文件
2. 放入 `resources/live2d/` 目录
3. 在 `yachiyo.model3.json` 的 `Expressions` 数组中注册
4. 在 `Live2DAnimationService` 的情感映射表中添加映射

### 添加新的 WebSocket 消息类型

1. 在 `WebSocketController.cpp` 中添加消息处理分支
2. 在前端 `useWebSocket.ts` 的 `handleMessage()` 中添加对应处理
3. 在 `types/index.ts` 中定义消息类型

### 修改数据库表结构

1. 修改 `database/init.sql`
2. 同步修改 `backend/config/init_database.sql`（Docker 用）
3. 更新对应的 Model（如 `User.hpp`）和 DAO 方法

## Git 工作流

### 分支策略

| 分支 | 用途 |
|------|------|
| `main` | 主分支，保持稳定可部署 |
| `dev` | 开发分支 |
| `feature/xxx` | 功能开发分支 |
| `fix/xxx` | Bug 修复分支 |

### 提交信息规范

```
<type>: <简短描述>

<详细描述（可选）>
```

类型：

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `refactor` | 代码重构 |
| `docs` | 文档更新 |
| `style` | 代码格式 |
| `test` | 测试相关 |
| `chore` | 构建/工具 |

示例：

```
fix: 修复 ConfigManager 无法处理 YAML 数组索引的问题

ConfigManager::get() 方法在遇到 YAML 数组节点时会直接调用 operator[](string)，
导致返回空值。添加 is_array() 检查，改用 std::stoul() 将路径段转为数字索引。
```
