## 📊 核心数据流

### 消息状态流转

```
PENDING (待处理)
    ↓
PROCESSING (处理中)
    ├─ 调用 OpenClaw API
    ├─ 翻译处理
    ├─ 语音生成
    ├─ 动作计算
    ↓
COMPLETED (已完成)
    ├─ 保存响应
    ├─ 推送 WebSocket
    ├─ 清理资源
    ↓
显示给用户
```

### 队列处理流程

```
入队速率: 10 msg/min (受限)
处理速率: 4 worker × 10 batch = 40 msg/min
队列大小: 最大 1000 条消息

吞吐量: 40 msg/min >> 10 msg/min 入队速率
结论: 队列永不溢出 ✓
```

## 🔐 安全性保障

### 多层防护

```
Layer 1: 速率限制
        └─ 防止消息轰炸
        
Layer 2: IP 黑名单
        └─ 防止已知恶意用户
        
Layer 3: 敏感词过滤
        └─ 防止有害内容
        
Layer 4: 启发式分析
        └─ 检测垃圾信息特征
        
Layer 5: 行为分析
        └─ 检测异常用户模式
        
Layer 6: 人工审核
        └─ 标记可疑内容供人工检查
```

### 审核通过率

假设各层通过率:
- Layer 1-3: 99% (快速过滤)
- Layer 4-5: 95% (深度分析)
- Layer 6: 98% (人工审核)

总通过率 ≈ 99% × 99% × 99% × 95% × 95% × 98% ≈ 85%

这意味着只有 15% 的消息需要人工标记审核。

## ⚡ 性能优化策略

### 响应时间分解

```
消息提交到虚拟形象反应的总时间: ~2 秒 (目标)

时间分解:
├─ 安全审核: 200 ms     (6层检查，并行执行)
├─ 数据库存储: 50 ms    (异步写入)
├─ 消息入队: 10 ms      (内存操作)
├─ OpenClaw 处理: 800 ms (最耗时)
├─ 翻译: 300 ms         (API 调用)
├─ 语音生成: 400 ms     (GPT-SoVITS)
├─ 动作计算: 100 ms     (本地计算)
├─ WebSocket 推送: 50 ms
└─ 总计: ~1910 ms ≈ 2 秒 ✓

优化方向:
- OpenClaw: 缓存常见回应
- 翻译: 缓存常见短语
- 语音: 预合成常用音频
- 并行处理: 多线程执行
```

### 缓存策略

```
翻译缓存
├─ 命中率: ~70% (常用短语)
├─ 节省时间: 300 ms
├─ TTL: 168 小时

响应缓存
├─ 命中率: ~30% (相似问题)
├─ 节省时间: 1000 ms
├─ TTL: 24 小时

音频缓存
├─ 命中率: ~40% (重复内容)
├─ 节省时间: 400 ms
├─ 容量: 1 GB
```
