## 1. 服务器准备

### 硬件要求

| 规格 | 最低 | 推荐 | 说明 |
|------|------|------|------|
| CPU | 2 核 | 4 核 | C++ 编译需要较多 CPU |
| 内存 | 4 GB | 8 GB | Docker 编译后端时内存占用高 |
| 硬盘 | 20 GB SSD | 50 GB SSD | Docker 镜像 + 数据库 + 日志 |
| GPU | 不需要 | 不需要 | 仅 GPT-SoVITS 需要 NVIDIA GPU |

### 操作系统

支持 Arch Linux / Debian 12+ / Ubuntu 22.04+，以下命令以 Arch Linux 为主，Debian/Ubuntu 等效命令会标注。

### 防火墙端口

只需对外开放 3 个端口：

| 端口 | 用途 |
|------|------|
| 22 | SSH |
| 80 | HTTP（重定向到 HTTPS） |
| 443 | HTTPS |

> 其他端口（8080/9001/3000/5432/6379 等）全部走内网，由 Nginx 反向代理，**不对外暴露**。

## 2. 安装 Docker

**Arch Linux:**

```bash
sudo pacman -S docker docker-compose
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
```

> ⚠️ 加完组后需要**重新登录**才生效。

**Debian / Ubuntu:**

```bash
# 安装 Docker 官方源
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/$(. /etc/os-release && echo "$ID")/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/$(. /etc/os-release && echo "$ID") \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 安装
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
```

验证：

```bash
docker --version
docker compose version
```

## 4. 创建 .env 文件

在项目根目录创建 `.env`，Docker Compose 会自动读取：

```bash
cd /opt/yachiyo
cat > .env << 'ENVEOF'
# ==================== 必须填写 ====================

# JWT 签名密钥（用下面的命令生成一个随机的）
JWT_SECRET_KEY=替换为你生成的密钥

# DeepSeek API Key（用于 AI 对话 + 内容审核）
DEEPSEEK_API_KEY=sk-你的DeepSeek密钥

# 百度翻译（APPID 和密钥在同一个页面获取: https://fanyi-api.baidu.com/manage/developer）
BAIDU_TRANSLATE_APPID=你的APPID
BAIDU_TRANSLATE_API_KEY=你的密钥

# ==================== 可选修改 ====================

# 数据库密码（默认 postgres，生产环境建议修改）
# POSTGRES_PASSWORD=你的数据库密码

# OpenClaw 地址（如果部署了的话）
# OPENCLAW_ENDPOINT=http://host.docker.internal:8000
ENVEOF
```

生成随机 JWT 密钥：

```bash
openssl rand -hex 32
```

### 关于百度翻译 APPID

百度翻译开放平台的"开发者信息"页面 (https://fanyi-api.baidu.com/manage/developer) 上只有两个东西：

- **APPID**：一串数字，如 `20150630000000001`
- **密钥**：一串字母数字，如 `abc1234567890`

> 没有所谓的 "APP ID"。就是 **APPID**（一个词，没有空格），页面上直接叫这个名字。

在 `.env` 中这样填：

```
BAIDU_TRANSLATE_APPID=20150630000000001
BAIDU_TRANSLATE_API_KEY=abc1234567890
```

## 5. 编辑 config.yaml

主要需要编辑两个配置文件。

### 5.1 全局配置 `config/config.yaml`

这个文件的敏感值支持 `${ENV_VAR}` 语法从环境变量读取，所以**如果你已经在 `.env` 中填好了密钥，大部分字段不需要改**。

需要确认的字段：

```yaml
# AI 配置段
ai:
  deepseek:
    api_key: "${DEEPSEEK_API_KEY}"      # 从 .env 读取，不用改

# 翻译配置段
translation:
  services:
    - name: "baidu"
      appid: "${BAIDU_TRANSLATE_APPID}"   # 从 .env 读取
      api_key: "${BAIDU_TRANSLATE_API_KEY}"

# JWT 配置段
jwt:
  secret_key: "${JWT_SECRET_KEY}"         # 从 .env 读取
```

### 5.2 后端配置 `backend/config/config.yaml`

同理，大部分字段从环境变量读取。如果你想手动填写（不用环境变量），直接把值写进去：

```yaml
translation:
  engines:
    - name: "baidu"
      appid: "你的APPID数字"
      api_key: "你的密钥"
```

## 6. 启动服务

```bash
cd /opt/yachiyo

# 方案 A: 一次性启动全部
docker compose up -d

# 方案 B: 分步启动（推荐首次部署用，方便排查问题）
docker compose up -d postgres redis          # 先启动数据库
docker compose up -d backend                  # 再启动后端（等 PG 和 Redis 健康后）
docker compose up -d frontend                 # 再启动前端
docker compose up -d nginx                    # 最后启动 Nginx
docker compose up -d bridge                   # 桥接服务（可选，需要 OpenClaw 时启动）

# 可选：监控和管理工具
docker compose up -d prometheus grafana       # 监控
docker compose up -d pgadmin redis-commander  # 管理工具
```

> 首次启动会触发 Docker 构建 C++ 后端，**编译可能需要 5~15 分钟**，取决于服务器性能。  
> 建议用 `docker compose up -d --build backend` 单独构建后端并观察日志。

查看构建进度：

```bash
docker compose logs -f backend
```

## 8. 启用 HTTPS

你已经完成了 Cloudflare SSL 配置。现在需要把 **Origin Certificate** 放到服务器上。

### 8.1 上传证书

你之前在 Cloudflare 生成的 Origin Certificate（如果还没保存下来，回 Cloudflare → SSL/TLS → Origin Server 重新创建）：

```bash
# 在服务器上创建 ssl 目录
mkdir -p /opt/yachiyo/ssl

# 方法 1: 用 nano/vim 手动粘贴证书内容
nano /opt/yachiyo/ssl/cert.pem    # 粘贴 Origin Certificate（-----BEGIN CERTIFICATE----- 开头）
nano /opt/yachiyo/ssl/key.pem     # 粘贴 Private Key（-----BEGIN PRIVATE KEY----- 开头）

# 方法 2: 从本地 scp 上传
# scp cert.pem key.pem user@服务器IP:/opt/yachiyo/ssl/

# 设置权限（Private Key 只允许 owner 读取）
chmod 600 /opt/yachiyo/ssl/key.pem
chmod 644 /opt/yachiyo/ssl/cert.pem
```

### 8.2 编辑 nginx.conf

项目根目录的 `nginx.conf` 已经有 SSL 相关配置（被注释了），取消注释即可：

```nginx
# 把 HTTP 重定向到 HTTPS
server {
    listen 80;
    server_name 你的域名;
    return 301 https://$host$request_uri;
}

# HTTPS 配置
server {
    listen 443 ssl http2;
    server_name 你的域名;

    ssl_certificate /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # 其余 location 配置不变...
}
```

> Docker Compose 已经将 `./ssl` 目录挂载到了容器内 `/etc/nginx/ssl`，不需要额外配置。

### 8.3 重启 Nginx

```bash
docker compose restart nginx
```

### 8.4 验证 HTTPS

```bash
curl -I https://你的域名
# 期望: HTTP/2 200 或 HTTP/1.1 200
```

## 9. 安全加固

### 必做

```bash
# 1. 防火墙（只开放 SSH/HTTP/HTTPS）

# UFW (Debian/Ubuntu):
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

# iptables (Arch):
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -P INPUT DROP
sudo iptables-save > /etc/iptables/iptables.rules
```

### 建议

- [ ] `.env` 中 `JWT_SECRET_KEY` 已设置为 ≥32 字符的随机字符串
- [ ] 数据库密码已从默认的 `postgres` 修改
- [ ] `config.yaml` 中 `cors_origins` 已改为你的域名（不要用 `*`）
- [ ] 不启动或不对外暴露 pgAdmin / Redis Commander
- [ ] Grafana 密码已从默认 `admin` 修改

## 11. 手动裸机部署（备选）

如果不想用 Docker：

### 11.1 安装系统依赖

**Arch Linux:**

```bash
sudo pacman -S base-devel cmake ninja gcc git \
    openssl yaml-cpp postgresql-libs hiredis curl \
    nlohmann-json postgresql redis nginx nodejs npm
```

**Debian / Ubuntu:**

```bash
sudo apt-get install -y build-essential cmake ninja-build gcc g++ git \
    libssl-dev libyaml-cpp-dev libpq-dev libhiredis-dev libcurl4-openssl-dev \
    nlohmann-json3-dev pkg-config \
    postgresql postgresql-contrib redis-server nginx nodejs npm
```

### 11.2 初始化数据库

```bash
sudo systemctl enable --now postgresql
sudo -u postgres psql -c "CREATE DATABASE yachiyo;"
sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '你的数据库密码';"
sudo -u postgres psql -d yachiyo -f /opt/yachiyo/database/init.sql
```

### 11.3 构建后端

```bash
cd /opt/yachiyo/backend
mkdir -p build && cd build
cmake .. -G "Ninja" -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_STANDARD=20
ninja
```

### 11.4 构建前端

```bash
cd /opt/yachiyo/frontend
npm ci
npm run build
```

### 11.5 创建 systemd 服务

```bash
# 后端
sudo tee /etc/systemd/system/yachiyo-backend.service << 'EOF'
[Unit]
Description=Yachiyo Backend
After=network.target postgresql.service redis.service

[Service]
Type=simple
User=yachiyo
WorkingDirectory=/opt/yachiyo/backend
ExecStart=/opt/yachiyo/backend/build/yachiyo_cpp --config-dir /opt/yachiyo/backend/config --env production
Restart=always
RestartSec=5
Environment=DB_HOST=localhost
Environment=DB_PASSWORD=your_database_password
Environment=REDIS_HOST=localhost
Environment=JWT_SECRET_KEY=your-jwt-secret-key

[Install]
WantedBy=multi-user.target
EOF

# 前端
sudo tee /etc/systemd/system/yachiyo-frontend.service << 'EOF'
[Unit]
Description=Yachiyo Frontend
After=network.target

[Service]
Type=simple
User=yachiyo
WorkingDirectory=/opt/yachiyo/frontend
ExecStart=/usr/bin/npx serve -s dist -l 3000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo useradd -r -s /bin/bash -m yachiyo
sudo chown -R yachiyo:yachiyo /opt/yachiyo
sudo systemctl daemon-reload
sudo systemctl enable --now yachiyo-backend yachiyo-frontend
```

### 11.6 配置 Nginx

```bash
sudo cp /opt/yachiyo/nginx.conf /etc/nginx/nginx.conf
# 将 Docker 内部域名改为 localhost
sudo sed -i 's/server backend:8080/server localhost:8080/' /etc/nginx/nginx.conf
sudo sed -i 's/server backend:9001/server localhost:9001/' /etc/nginx/nginx.conf
sudo sed -i 's/server frontend:3000/server localhost:3000/' /etc/nginx/nginx.conf
sudo nginx -t && sudo systemctl enable --now nginx
```

## 12. GPT-SoVITS 语音合成（可选）

GPT-SoVITS 是独立的 Python 服务，用于生成虚拟形象的语音。

### 硬件要求

**必须要 NVIDIA 独立显卡。Intel 核显不能用。**

原因：GPT-SoVITS 依赖 PyTorch CUDA 加速。Intel 核显（UHD/Iris）没有 CUDA 支持，PyTorch 无法将其识别为 GPU 设备。核显的"共享显存"是从内存划出的，既没有独立计算核心，也没有足够的显存，推理速度不会比纯 CPU 快。

| 方案 | 说明 |
|------|------|
| 有 NVIDIA GPU | 正常部署，详见 `docs/GPT-SoVITS部署指南.md` |
| 没有 GPU | 设置 `gpt_sovits.enabled: false` 禁用语音，AI 只输出文字 |
| 想要语音但没本地 GPU | 租一台 GPU 云服务器（AutoDL/RunPod），部署 GPT-SoVITS，通过内网 HTTP 调用 |
| CPU 推理 | 技术上可以，但每条语音 5~30 秒，不适合实时直播 |

### 快速对接

如果你有 GPU 且已部署好 GPT-SoVITS（API 跑在 `http://GPU服务器:5000`），只需在 `config/config.yaml` 中：

```yaml
gpt_sovits:
  enabled: true
  api_endpoint: "http://GPU服务器地址:5000"
```

详细安装流程见 `docs/GPT-SoVITS部署指南.md`。

## 13. 常见问题

### Q: 后端连不上数据库

1. 检查 PostgreSQL 是否运行：`docker compose ps postgres`
2. 检查密码是否一致：`.env` 中的 `DB_PASSWORD` 要和 `config.yaml` 中 `database.password` 一致
3. Docker 模式下 host 是 `postgres`（容器名），裸机是 `localhost`

### Q: 前端无法调用 API

1. 检查 `VITE_API_BASE_URL` 是否正确
2. 检查 Nginx 是否正确代理了 `/api` 路径

### Q: WebSocket 连接失败

1. Nginx 中 `/ws` 路径是否有 WebSocket 升级头配置
2. Cloudflare → Network → WebSockets 是否已开启（免费版默认开启）
3. 前端是否使用了 `wss://` 协议（Cloudflare 要求 HTTPS）

### Q: Docker 构建后端很慢 / OOM

C++ 编译消耗大量内存。如果 OOM，尝试：

```bash
# 限制并行编译数
docker compose build --build-arg CMAKE_BUILD_PARALLEL_LEVEL=2 backend

# 或者不用缓存重建
docker compose build --no-cache backend
```

### Q: Cloudflare 报 522/524 错误

- 522: 服务器不可达 → 检查防火墙是否开放了 80/443
- 524: 请求超时 → 检查 Nginx 和后端是否在运行

### Q: 百度翻译报 54001 签名错误

检查 APPID 和密钥是否正确填入。APPID 是纯数字，密钥是字母数字组合。两个值在百度翻译开放平台 → 开发者信息页面获取。

## 常用运维命令

```bash
# 查看所有容器
docker compose ps

# 查看日志
docker compose logs -f backend
docker compose logs -f bridge

# 停止所有
docker compose down

# 更新代码后重建
cd /opt/yachiyo && git pull origin main
docker compose up -d --build

# 备份数据库
docker compose exec postgres pg_dump -U postgres yachiyo > backup_$(date +%Y%m%d).sql

# 恢复数据库
docker compose exec -T postgres psql -U postgres yachiyo < backup.sql

# 只重建后端
docker compose up -d --build backend
```
