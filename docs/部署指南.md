# Yachiyo 部署指南

> **版本**: v4.0.0  
> **更新**: 2026年4月  
> **适用系统**: Arch Linux / Debian / Ubuntu  
> **部署方式**: 分阶段脚本部署（主推）/ Docker Compose / 裸机部署  
> **配置键路径**: 已与 `Application.cpp` 代码完全对齐

---

## 总览：部署分为 7 个阶段

每个阶段都有对应的**独立脚本**，可以单独执行和重试。全流程也可以用一键脚本 `deploy-server.sh` 串联完成。

```
阶段 1 → 阶段 2 → 阶段 3 → 阶段 4 → 阶段 5 → 阶段 6 → 阶段 7
系统准备   环境安装   代码部署   密钥配置   构建启动   验证测试   HTTPS+加固
```

| 阶段 | 脚本 | 说明 | 耗时 |
|------|------|------|------|
| 1. 系统准备 | `yachiyo-stage1-prepare.sh` | 检查硬件、更新系统、配置防火墙 | ~2 分钟 |
| 2. 环境安装 | `yachiyo-stage2-install.sh` | 安装 Docker / 编译工具链 | ~3 分钟 |
| 3. 代码部署 | `yachiyo-stage3-code.sh` | 克隆/更新项目代码 | ~1 分钟 |
| 4. 密钥配置 | `yachiyo-stage4-config.sh` | 生成 .env + 交互式填写密钥 | ~2 分钟 |
| 5. 构建启动 | `yachiyo-stage5-build.sh` | 编译后端 + 构建前端 + 启动全部 | ~10 分钟 |
| 6. 验证测试 | `yachiyo-stage6-verify.sh` | 健康检查 + 功能验证 | ~1 分钟 |
| 7. HTTPS 加固 | `yachiyo-stage7-secure.sh` | 证书部署 + Nginx SSL + 安全加固 | ~3 分钟 |

## 1. 硬件与系统要求

### 硬件要求

| 规格 | 最低 | 推荐 | 说明 |
|------|------|------|------|
| CPU | 2 核 | 4 核 | C++ 编译需要较多 CPU |
| 内存 | 4 GB | 8 GB | Docker 编译后端时内存占用高 |
| 硬盘 | 20 GB SSD | 50 GB SSD | Docker 镜像 + 数据库 + 日志 |
| GPU | 不需要 | 不需要 | 仅 GPT-SoVITS 需要 NVIDIA GPU |

### 操作系统

支持 Arch Linux / Debian 12+ / Ubuntu 22.04+。脚本会自动检测发行版并使用对应的包管理器。

### 防火墙端口

只需对外开放 3 个端口：

| 端口 | 用途 |
|------|------|
| 22 | SSH |
| 80 | HTTP（重定向到 HTTPS） |
| 443 | HTTPS |

> 其他端口（8080/9001/3000/5432/6379 等）全部走内网，由 Nginx 反向代理，**不对外暴露**。

### 需要提前准备的东西

在开始部署之前，确保你已经拿到了以下信息：

| 项目 | 获取方式 | 必须? |
|------|----------|-------|
| DeepSeek API Key | https://platform.deepseek.com/api_keys | ✅ 必须 |
| 百度翻译 APPID + 密钥 | https://fanyi-api.baidu.com/manage/developer | ✅ 必须 |
| Cloudflare Origin Certificate | Cloudflare → SSL/TLS → Origin Server | ⬜ 上 HTTPS 时需要 |
| OpenClaw 服务地址 | 自行部署或找服务提供商 | ⬜ 可选 |

## 2. 一键部署（推荐）

如果你只想一条命令搞定，直接在全新服务器上运行：

```bash
# 方法 1: 先克隆再执行
git clone https://github.com/ermaotie6/yachiyoooooooo.git /opt/yachiyo
cd /opt/yachiyo
chmod +x scripts/deploy-server.sh
sudo bash scripts/deploy-server.sh docker
```

```bash
# 方法 2: 一行远程执行（适合全自动化）
curl -fsSL https://raw.githubusercontent.com/ermaotie6/yachiyoooooooo/main/scripts/deploy-server.sh | sudo bash
```

一键脚本 `deploy-server.sh` 内部会自动执行所有阶段：
1. 检测发行版（Arch / Debian / Ubuntu）
2. 安装 Docker 和 Docker Compose
3. 克隆/更新项目代码
4. 生成 `.env` 文件（自动生成 JWT 密钥）
5. 构建并启动全部 Docker 容器
6. 执行健康检查
7. 打印访问信息

> ⚠️ 一键脚本执行完后，你仍然需要手动编辑 `.env` 填入 API 密钥，然后重启服务使配置生效。

**如果想要更精细的控制**，请按下面的分阶段操作。

## 3. 阶段 1：系统准备

> **目标**：确认服务器满足要求，更新系统，配置防火墙。

### 脚本方式

```bash
# 创建并执行阶段 1 脚本
bash -c 'cat > /tmp/yachiyo-stage1.sh << '\''STAGE1'\''
#!/usr/bin/env bash
set -euo pipefail

GREEN="\033[0;32m"; YELLOW="\033[1;33m"; RED="\033[0;31m"; BLUE="\033[0;34m"; NC="\033[0m"
info()    { echo -e "${BLUE}[阶段1]${NC} $*"; }
ok()      { echo -e "${GREEN}[✓]${NC} $*"; }
warn()    { echo -e "${YELLOW}[!]${NC} $*"; }
fail()    { echo -e "${RED}[✗]${NC} $*"; }

echo -e "${BLUE}════════ 阶段 1: 系统准备 ════════${NC}"

# 检查 root 或 sudo
if [ "$EUID" -ne 0 ]; then
    fail "请使用 sudo 或 root 用户执行"
    exit 1
fi

# 检测发行版
if [ -f /etc/os-release ]; then
    . /etc/os-release
    DISTRO_ID="${ID}"
else
    fail "无法识别的发行版"
    exit 1
fi

case "$DISTRO_ID" in
    arch|manjaro|endeavouros) DISTRO_FAMILY="arch" ;;
    debian|ubuntu|linuxmint|pop) DISTRO_FAMILY="debian" ;;
    *) fail "不支持: $DISTRO_ID (仅支持 Arch/Debian/Ubuntu)"; exit 1 ;;
esac
ok "系统: ${PRETTY_NAME} (${DISTRO_FAMILY} 系列)"

# 检查硬件
CPU_CORES=$(nproc)
RAM_MB=$(free -m | awk '/Mem:/ {print $2}')
DISK_GB=$(df -BG / | awk 'NR==2 {gsub(/G/,""); print $4}')

info "CPU: ${CPU_CORES} 核 | 内存: ${RAM_MB} MB | 可用磁盘: ${DISK_GB} GB"

WARNINGS=0
[ "$CPU_CORES" -lt 2 ] && { warn "CPU 不足 2 核，编译会非常慢"; WARNINGS=$((WARNINGS+1)); }
[ "$RAM_MB" -lt 3500 ] && { warn "内存不足 4GB，Docker 编译可能 OOM"; WARNINGS=$((WARNINGS+1)); }
[ "$DISK_GB" -lt 15 ] && { warn "磁盘不足 15GB，空间可能不够"; WARNINGS=$((WARNINGS+1)); }

if [ $WARNINGS -eq 0 ]; then
    ok "硬件检查全部通过"
else
    warn "有 $WARNINGS 项警告，建议升级后再部署"
fi

# 更新系统
info "更新系统包..."
case "$DISTRO_FAMILY" in
    arch)   pacman -Syu --noconfirm ;;
    debian) apt-get update -y && apt-get upgrade -y ;;
esac
ok "系统更新完成"

# 安装基础工具
info "安装基础工具..."
case "$DISTRO_FAMILY" in
    arch)   pacman -S --noconfirm --needed base-devel git curl wget openssl ca-certificates ;;
    debian) apt-get install -y build-essential git curl wget openssl ca-certificates gnupg lsb-release ;;
esac
ok "基础工具安装完成"

# 配置防火墙
info "配置防火墙..."
case "$DISTRO_FAMILY" in
    debian)
        if command -v ufw &>/dev/null; then
            ufw --force reset
            ufw default deny incoming
            ufw default allow outgoing
            ufw allow 22/tcp
            ufw allow 80/tcp
            ufw allow 443/tcp
            ufw --force enable
            ok "UFW 防火墙已配置 (开放 22/80/443)"
        else
            apt-get install -y ufw
            ufw default deny incoming
            ufw default allow outgoing
            ufw allow 22/tcp
            ufw allow 80/tcp
            ufw allow 443/tcp
            ufw --force enable
            ok "UFW 已安装并配置"
        fi
        ;;
    arch)
        if command -v iptables &>/dev/null; then
            iptables -F
            iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
            iptables -A INPUT -i lo -j ACCEPT
            iptables -A INPUT -p tcp --dport 22 -j ACCEPT
            iptables -A INPUT -p tcp --dport 80 -j ACCEPT
            iptables -A INPUT -p tcp --dport 443 -j ACCEPT
            iptables -P INPUT DROP
            mkdir -p /etc/iptables
            iptables-save > /etc/iptables/iptables.rules
            systemctl enable iptables 2>/dev/null || true
            ok "iptables 防火墙已配置 (开放 22/80/443)"
        fi
        ;;
esac

echo ""
ok "阶段 1 完成 ✓"
echo -e "  下一步: ${BLUE}sudo bash /tmp/yachiyo-stage2.sh${NC}"
STAGE1
chmod +x /tmp/yachiyo-stage1.sh'
sudo bash /tmp/yachiyo-stage1.sh
```

## 4. 阶段 2：环境安装

> **目标**：安装 Docker 和 Docker Compose。

### 脚本方式

```bash
bash -c 'cat > /tmp/yachiyo-stage2.sh << '\''STAGE2'\''
#!/usr/bin/env bash
set -euo pipefail

GREEN="\033[0;32m"; BLUE="\033[0;34m"; YELLOW="\033[1;33m"; NC="\033[0m"
info()  { echo -e "${BLUE}[阶段2]${NC} $*"; }
ok()    { echo -e "${GREEN}[✓]${NC} $*"; }
warn()  { echo -e "${YELLOW}[!]${NC} $*"; }

echo -e "${BLUE}════════ 阶段 2: 环境安装 ════════${NC}"

. /etc/os-release
case "$ID" in
    arch|manjaro|endeavouros) DISTRO_FAMILY="arch" ;;
    debian|ubuntu|linuxmint|pop) DISTRO_FAMILY="debian" ;;
    *) echo "不支持: $ID"; exit 1 ;;
esac

# 安装 Docker
if command -v docker &>/dev/null; then
    ok "Docker 已安装: $(docker --version)"
else
    info "安装 Docker..."
    case "$DISTRO_FAMILY" in
        arch)
            pacman -S --noconfirm --needed docker docker-compose docker-buildx
            ;;
        debian)
            install -m 0755 -d /etc/apt/keyrings
            curl -fsSL "https://download.docker.com/linux/${ID}/gpg" | \
                gpg --dearmor -o /etc/apt/keyrings/docker.gpg
            chmod a+r /etc/apt/keyrings/docker.gpg
            echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
                https://download.docker.com/linux/${ID} $(lsb_release -cs) stable" | \
                tee /etc/apt/sources.list.d/docker.list > /dev/null
            apt-get update
            apt-get install -y docker-ce docker-ce-cli containerd.io \
                docker-buildx-plugin docker-compose-plugin
            ;;
    esac
    ok "Docker 安装完成"
fi

# 启动 Docker
systemctl enable --now docker
ok "Docker 服务已启动"

# 将当前用户加入 docker 组
REAL_USER="${SUDO_USER:-$USER}"
if ! groups "$REAL_USER" 2>/dev/null | grep -q docker; then
    usermod -aG docker "$REAL_USER"
    warn "已将 $REAL_USER 加入 docker 组，重新登录后生效"
    warn "或运行: newgrp docker"
fi

# 验证 Docker Compose
if docker compose version &>/dev/null; then
    ok "Docker Compose (v2 插件): $(docker compose version --short)"
elif command -v docker-compose &>/dev/null; then
    ok "Docker Compose (独立版): $(docker-compose --version)"
else
    echo "Docker Compose 未安装"; exit 1
fi

echo ""
ok "阶段 2 完成 ✓"
echo -e "  下一步: ${BLUE}sudo bash /tmp/yachiyo-stage3.sh${NC}"
STAGE2
chmod +x /tmp/yachiyo-stage2.sh'
sudo bash /tmp/yachiyo-stage2.sh
```

```bash

```

## 5. 阶段 3：代码部署

> **目标**：将项目代码克隆到 `/opt/yachiyo`。

### 脚本方式

```bash
bash -c 'cat > /tmp/yachiyo-stage3.sh << '\''STAGE3'\''
#!/usr/bin/env bash
set -euo pipefail

GREEN="\033[0;32m"; BLUE="\033[0;34m"; YELLOW="\033[1;33m"; NC="\033[0m"
info()  { echo -e "${BLUE}[阶段3]${NC} $*"; }
ok()    { echo -e "${GREEN}[✓]${NC} $*"; }
warn()  { echo -e "${YELLOW}[!]${NC} $*"; }

INSTALL_DIR="/opt/yachiyo"
REPO_URL="https://github.com/ermaotie6/yachiyoooooooo.git"
BRANCH="main"

echo -e "${BLUE}════════ 阶段 3: 代码部署 ════════${NC}"

REAL_USER="${SUDO_USER:-$USER}"

if [ -d "$INSTALL_DIR/.git" ]; then
    info "项目目录已存在，拉取最新代码..."
    cd "$INSTALL_DIR"
    git fetch origin
    git reset --hard "origin/$BRANCH"
    git clean -fd
    ok "代码更新完成: $(git log --oneline -1)"
else
    info "克隆项目到 $INSTALL_DIR ..."
    mkdir -p "$INSTALL_DIR"
    chown "$REAL_USER:$REAL_USER" "$INSTALL_DIR"
    git clone --branch "$BRANCH" "$REPO_URL" "$INSTALL_DIR"
    chown -R "$REAL_USER:$REAL_USER" "$INSTALL_DIR"
    cd "$INSTALL_DIR"
    ok "项目克隆完成: $(git log --oneline -1)"
fi

# 确保脚本有执行权限
chmod +x "$INSTALL_DIR/scripts/"*.sh 2>/dev/null || true

# 展示项目结构
info "项目结构:"
echo "  $INSTALL_DIR/"
echo "  ├── backend/         C++ 后端 (Crow + PostgreSQL)"
echo "  ├── frontend/        Vue 3 前端 (Vite + PixiJS + Live2D)"
echo "  ├── bridge/          Node.js 桥接服务 (OpenClaw 代理)"
echo "  ├── database/        SQL 初始化脚本"
echo "  ├── config/          全局配置文件"
echo "  ├── resources/       Live2D 模型 + 头像配置"
echo "  ├── nginx.conf       Nginx 反向代理配置"
echo "  ├── docker-compose.yml"
echo "  └── scripts/         部署/启停脚本"

echo ""
ok "阶段 3 完成 ✓"
echo -e "  下一步: ${BLUE}sudo bash /tmp/yachiyo-stage4.sh${NC}"
STAGE3
chmod +x /tmp/yachiyo-stage3.sh'
sudo bash /tmp/yachiyo-stage3.sh
```

## 6. 阶段 4：密钥配置

> **目标**：生成 `.env` 文件，填入所有 API 密钥。

这是**唯一需要人工干预**的阶段——你需要填入自己的 API 密钥。

### 脚本方式（交互式）

```bash
bash -c 'cat > /tmp/yachiyo-stage4.sh << '\''STAGE4'\''
#!/usr/bin/env bash
set -euo pipefail

GREEN="\033[0;32m"; BLUE="\033[0;34m"; YELLOW="\033[1;33m"; RED="\033[0;31m"; NC="\033[0m"
info()  { echo -e "${BLUE}[阶段4]${NC} $*"; }
ok()    { echo -e "${GREEN}[✓]${NC} $*"; }
warn()  { echo -e "${YELLOW}[!]${NC} $*"; }
fail()  { echo -e "${RED}[✗]${NC} $*"; }

INSTALL_DIR="/opt/yachiyo"
ENV_FILE="$INSTALL_DIR/.env"

echo -e "${BLUE}════════ 阶段 4: 密钥配置 ════════${NC}"

if [ -f "$ENV_FILE" ]; then
    warn ".env 文件已存在"
    echo -e "  路径: ${YELLOW}$ENV_FILE${NC}"
    read -p "  是否覆盖重新配置? (y/N) " -n 1 -r
    echo
    if [[ ! $REPLY =~ ^[Yy]$ ]]; then
        ok "保留现有配置，跳过"
        exit 0
    fi
    cp "$ENV_FILE" "${ENV_FILE}.backup.$(date +%Y%m%d_%H%M%S)"
    ok "已备份现有 .env"
fi

# 自动生成 JWT 密钥
JWT_SECRET=$(openssl rand -hex 32)
ok "JWT 密钥已自动生成 (64 字符随机字符串)"

# 交互式填写密钥
echo ""
echo -e "${BLUE}请输入以下 API 密钥（直接回车可跳过，稍后编辑 .env 补充）:${NC}"
echo ""

read -p "  DeepSeek API Key (sk-开头): " DEEPSEEK_KEY
DEEPSEEK_KEY="${DEEPSEEK_KEY:-}"

read -p "  百度翻译 APPID (纯数字): " BAIDU_APPID
BAIDU_APPID="${BAIDU_APPID:-}"

read -p "  百度翻译密钥 (字母数字): " BAIDU_SECRET
BAIDU_SECRET="${BAIDU_SECRET:-}"

read -p "  数据库密码 (默认 postgres): " DB_PASS
DB_PASS="${DB_PASS:-postgres}"

# 生成 .env 文件
cat > "$ENV_FILE" <<ENVEOF
# ============================================================
# Yachiyo 环境变量配置
# 由 yachiyo-stage4-config.sh 于 $(date '+%Y-%m-%d %H:%M:%S') 生成
# ============================================================

# ===== JWT 签名密钥 (已自动生成) =====
JWT_SECRET_KEY=${JWT_SECRET}

# ===== DeepSeek API (AI 对话 + 内容审核) =====
DEEPSEEK_API_KEY=${DEEPSEEK_KEY}

# ===== 百度翻译 =====
# 获取地址: https://fanyi-api.baidu.com/manage/developer
# APPID 是一串纯数字，密钥是字母数字组合
BAIDU_TRANSLATE_APPID=${BAIDU_APPID}
BAIDU_TRANSLATE_API_KEY=${BAIDU_SECRET}

# ===== 数据库 =====
DATABASE_PASSWORD=${DB_PASS}

# ===== OpenClaw (可选，不部署则留空) =====
OPENCLAW_ENDPOINT=
OPENCLAW_API_KEY=

# ===== GPT-SoVITS 语音合成 (可选) =====
SOVITS_API_KEY=
ENVEOF

chmod 600 "$ENV_FILE"
ok ".env 文件已生成: $ENV_FILE"

# 验证必填项
MISSING=0
[ -z "$DEEPSEEK_KEY" ] && { warn "DeepSeek API Key 未填写 — AI 对话和内容审核将不可用"; MISSING=$((MISSING+1)); }
[ -z "$BAIDU_APPID" ]  && { warn "百度翻译 APPID 未填写 — 翻译功能将不可用"; MISSING=$((MISSING+1)); }
[ -z "$BAIDU_SECRET" ] && { warn "百度翻译密钥未填写 — 翻译功能将不可用"; MISSING=$((MISSING+1)); }

if [ $MISSING -gt 0 ]; then
    echo ""
    warn "有 $MISSING 项密钥未填写，稍后请编辑补充:"
    echo -e "  ${YELLOW}nano $ENV_FILE${NC}"
fi

echo ""
ok "阶段 4 完成 ✓"
echo -e "  下一步: ${BLUE}sudo bash /tmp/yachiyo-stage5.sh${NC}"
STAGE4
chmod +x /tmp/yachiyo-stage4.sh'
sudo bash /tmp/yachiyo-stage4.sh
```

### 关于百度翻译 APPID

百度翻译开放平台 "开发者信息" 页面 (https://fanyi-api.baidu.com/manage/developer) 上只有两个东西：

- **APPID**：一串数字，如 `20150630000000001`
- **密钥**：一串字母数字，如 `abc1234567890`

> 没有所谓的 "APP ID"。就是 **APPID**（一个词，没有空格），页面上直接叫这个名字。

## 7. 阶段 5：构建启动

> **目标**：编译 C++ 后端，构建 Vue 前端，启动所有 Docker 容器。

### 脚本方式

```bash
bash -c 'cat > /tmp/yachiyo-stage5.sh << '\''STAGE5'\''
#!/usr/bin/env bash
set -euo pipefail

GREEN="\033[0;32m"; BLUE="\033[0;34m"; YELLOW="\033[1;33m"; RED="\033[0;31m"; NC="\033[0m"
info()  { echo -e "${BLUE}[阶段5]${NC} $*"; }
ok()    { echo -e "${GREEN}[✓]${NC} $*"; }
warn()  { echo -e "${YELLOW}[!]${NC} $*"; }
fail()  { echo -e "${RED}[✗]${NC} $*"; }

INSTALL_DIR="/opt/yachiyo"

echo -e "${BLUE}════════ 阶段 5: 构建启动 ════════${NC}"

# 显示容器状态
echo ""
info "容器状态:"
$DC ps --format "table {{.Name}}\t{{.Status}}\t{{.Ports}}" 2>/dev/null || $DC ps

echo ""
ok "阶段 5 完成 ✓"
echo -e "  下一步: ${BLUE}sudo bash /tmp/yachiyo-stage6.sh${NC}"
```

## 9. 阶段 7：HTTPS 与安全加固

> **目标**：部署 SSL 证书，启用 HTTPS，执行安全加固。

### 前提

你需要 Cloudflare Origin Certificate。如果还没有：
1. 登录 Cloudflare → 选择域名 → SSL/TLS → Origin Server
2. 点击 "Create Certificate"
3. 保存 Certificate (cert.pem) 和 Private Key (key.pem)

### 脚本方式

```bash
bash -c 'cat > /tmp/yachiyo-stage7.sh << '\''STAGE7'\''
#!/usr/bin/env bash
set -euo pipefail

GREEN="\033[0;32m"; BLUE="\033[0;34m"; YELLOW="\033[1;33m"; RED="\033[0;31m"; NC="\033[0m"
info()  { echo -e "${BLUE}[阶段7]${NC} $*"; }
ok()    { echo -e "${GREEN}[✓]${NC} $*"; }
warn()  { echo -e "${YELLOW}[!]${NC} $*"; }
fail()  { echo -e "${RED}[✗]${NC} $*"; }

INSTALL_DIR="/opt/yachiyo"
SSL_DIR="$INSTALL_DIR/ssl"
NGINX_CONF="$INSTALL_DIR/nginx.conf"

echo -e "${BLUE}════════ 阶段 7: HTTPS 与安全加固 ════════${NC}"

cd "$INSTALL_DIR"

DC="docker compose"
$DC version &>/dev/null || DC="docker-compose"

# ===== 步骤 1: SSL 证书 =====
echo ""
echo -e "${BLUE}[步骤 1] SSL 证书部署${NC}"

mkdir -p "$SSL_DIR"

if [ -f "$SSL_DIR/cert.pem" ] && [ -f "$SSL_DIR/key.pem" ]; then
    ok "SSL 证书已存在"
else
    warn "未检测到 SSL 证书文件"
    echo ""
    echo "请选择证书部署方式:"
    echo "  1) 手动粘贴证书内容 (推荐)"
    echo "  2) 从本地路径复制"
    echo "  3) 跳过 HTTPS 配置"
    read -p "选择 (1/2/3): " -n 1 -r
    echo ""

    case "$REPLY" in
        1)
            echo "请粘贴 Origin Certificate 内容 (以 -----BEGIN CERTIFICATE----- 开头):"
            echo "粘贴完成后，输入 EOF 并回车:"
            CERT_CONTENT=""
            while IFS= read -r line; do
                [ "$line" = "EOF" ] && break
                CERT_CONTENT+="$line"$'\n'
            done
            echo "$CERT_CONTENT" > "$SSL_DIR/cert.pem"
            
            echo "请粘贴 Private Key 内容 (以 -----BEGIN PRIVATE KEY----- 开头):"
            echo "粘贴完成后，输入 EOF 并回车:"
            KEY_CONTENT=""
            while IFS= read -r line; do
                [ "$line" = "EOF" ] && break
                KEY_CONTENT+="$line"$'\n'
            done
            echo "$KEY_CONTENT" > "$SSL_DIR/key.pem"
            ;;
        2)
            read -p "cert.pem 路径: " CERT_PATH
            read -p "key.pem 路径: " KEY_PATH
            cp "$CERT_PATH" "$SSL_DIR/cert.pem"
            cp "$KEY_PATH" "$SSL_DIR/key.pem"
            ;;
        3)
            warn "跳过 HTTPS 配置"
            echo ""
            echo -e "${BLUE}[步骤 2] 安全加固检查表${NC}"
            # 直接跳到安全加固
            ;;
    esac

    if [ -f "$SSL_DIR/cert.pem" ] && [ -f "$SSL_DIR/key.pem" ]; then
        chmod 644 "$SSL_DIR/cert.pem"
        chmod 600 "$SSL_DIR/key.pem"
        ok "SSL 证书文件已就位"
    fi
fi

# ===== 步骤 2: 启用 Nginx SSL =====
if [ -f "$SSL_DIR/cert.pem" ] && [ -f "$SSL_DIR/key.pem" ]; then
    echo ""
    echo -e "${BLUE}[步骤 2] Nginx SSL 配置${NC}"
    info "SSL 证书路径: $SSL_DIR/"
    info "docker-compose.yml 已将 ./ssl 挂载到容器内 /etc/nginx/ssl"
    info "请编辑 nginx.conf 取消 SSL 相关注释:"
    echo ""
    echo "  取消注释以下行:"
    echo "    listen 443 ssl http2;"
    echo "    ssl_certificate /etc/nginx/ssl/cert.pem;"
    echo "    ssl_certificate_key /etc/nginx/ssl/key.pem;"
    echo "    ssl_protocols TLSv1.2 TLSv1.3;"
    echo ""
    read -p "是否现在编辑 nginx.conf? (y/N) " -n 1 -r
    echo ""
    if [[ $REPLY =~ ^[Yy]$ ]]; then
        ${EDITOR:-nano} "$NGINX_CONF"
    fi

    info "重启 Nginx..."
    $DC restart nginx
    sleep 2
    ok "Nginx 已重启"
fi

# ===== 步骤 3: 安全加固检查 =====
echo ""
echo -e "${BLUE}[步骤 3] 安全加固检查表${NC}"

# 检查 JWT 密钥
JWT_KEY=$(grep "JWT_SECRET_KEY=" "$INSTALL_DIR/.env" 2>/dev/null | cut -d= -f2)
JWT_LEN=${#JWT_KEY}
if [ "$JWT_LEN" -ge 32 ]; then
    ok "JWT 密钥长度: $JWT_LEN 字符 (≥32 ✓)"
else
    warn "JWT 密钥长度: $JWT_LEN 字符 (建议 ≥32)"
fi

# 检查数据库密码
DB_PASS=$(grep "DATABASE_PASSWORD=" "$INSTALL_DIR/.env" 2>/dev/null | cut -d= -f2)
if [ "$DB_PASS" = "postgres" ] || [ -z "$DB_PASS" ]; then
    warn "数据库密码仍为默认值 'postgres'，生产环境请修改"
else
    ok "数据库密码已自定义"
fi

# 检查 CORS
if grep -q 'cors_origins: "\*"' "$INSTALL_DIR/backend/config/config.yaml" 2>/dev/null; then
    warn "CORS 设为 * (允许所有域名)，生产环境请改为你的域名"
else
    ok "CORS 配置正常"
fi

# 检查管理工具
PGADMIN_RUNNING=$($DC ps pgadmin 2>/dev/null | grep -c "Up" || echo "0")
REDIS_CMD_RUNNING=$($DC ps redis-commander 2>/dev/null | grep -c "Up" || echo "0")
if [ "$PGADMIN_RUNNING" -gt 0 ] || [ "$REDIS_CMD_RUNNING" -gt 0 ]; then
    warn "pgAdmin 或 Redis Commander 正在运行 — 生产环境建议关闭:"
    echo "  $DC stop pgadmin redis-commander"
else
    ok "管理工具未对外暴露"
fi

echo ""
ok "阶段 7 完成 ✓"
echo ""
echo -e "${GREEN}🎀 Yachiyo 部署全部完成！${NC}"
STAGE7
chmod +x /tmp/yachiyo-stage7.sh'
sudo bash /tmp/yachiyo-stage7.sh
```

## 11. GPT-SoVITS 语音合成（可选）

GPT-SoVITS 是独立的 Python 服务，用于生成虚拟形象的语音。

### 硬件要求

**必须要 NVIDIA 独立显卡。Intel 核显不能用。**

原因：GPT-SoVITS 依赖 PyTorch CUDA 加速。Intel 核显（UHD/Iris）没有 CUDA 支持，PyTorch 无法将其识别为 GPU 设备。

| 方案 | 说明 |
|------|------|
| 有 NVIDIA GPU | 正常部署，详见 `docs/GPT-SoVITS部署指南.md` |
| 没有 GPU | 设置 `gpt_sovits.enabled: false` 禁用语音，AI 只输出文字 |
| 想要语音但没本地 GPU | 租一台 GPU 云服务器（AutoDL/RunPod），部署 GPT-SoVITS，通过 HTTP 调用 |
| CPU 推理 | 技术上可以，但每条语音 5~30 秒，不适合实时直播 |

### 快速对接

如果已部署好 GPT-SoVITS API，只需修改配置：

```bash
# 编辑 backend/config/config.yaml
gpt_sovits:
  enabled: true
  api_endpoint: "http://GPU服务器地址:5000"
  mode: "gpu"           # 或 "cpu"
  timeout_seconds: 15   # GPU 模式可以设低
```

## 13. 常见问题

### Q: 后端连不上数据库

```bash
# 1. 检查 PostgreSQL 是否运行
docker compose ps postgres
# 2. 检查密码是否一致
grep DB_PASSWORD .env
grep password backend/config/config.yaml
# 3. Docker 模式下 host 是 postgres (容器名)，裸机是 localhost
```

### Q: 前端无法调用 API

```bash
# 1. 检查 Nginx 是否正确代理了 /api 路径
curl -I http://localhost/api/v1/health
# 2. 检查 Nginx 日志
docker compose logs nginx
```

### Q: WebSocket 连接失败

1. Nginx 中 `/ws` 路径是否有 WebSocket 升级头配置 — 项目自带的 `nginx.conf` 已配置好
2. Cloudflare → Network → WebSockets 是否已开启（免费版默认开启）
3. 前端是否使用了 `wss://` 协议（走 Cloudflare 必须 HTTPS）

### Q: Docker 构建后端很慢 / OOM

```bash
# 限制并行编译数 (降低内存占用)
docker compose build --build-arg CMAKE_BUILD_PARALLEL_LEVEL=2 backend

# 查看内存使用
docker stats --no-stream

# 如果反复 OOM，考虑增加 swap
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

### Q: Cloudflare 报 522/524 错误

- **522 (Connection Timed Out)**: 服务器不可达 → 检查防火墙是否开放了 80/443
- **524 (A Timeout Occurred)**: 请求超时 → 检查 Nginx 和后端是否在运行

```bash
# 快速诊断
sudo ufw status                    # 防火墙规则
docker compose ps                  # 容器状态
curl -I http://localhost           # 本地是否正常
```

### Q: 百度翻译报 54001 签名错误

检查 APPID 和密钥是否正确填入。APPID 是纯数字，密钥是字母数字组合。两个值在百度翻译开放平台 → 开发者信息页面获取。

```bash
# 验证 .env 中的值
grep BAIDU .env
```

### Q: 如何从某个阶段重新开始？

每个阶段脚本都是幂等的（可重复执行），直接重新运行对应的阶段脚本即可：

```bash
sudo bash /tmp/yachiyo-stage4.sh    # 重新配置密钥
sudo bash /tmp/yachiyo-stage5.sh    # 重新构建启动
sudo bash /tmp/yachiyo-stage6.sh    # 重新验证
```

### Q: 如何完全卸载？

```bash
cd /opt/yachiyo
docker compose down -v              # 停止容器并删除数据卷
cd /
sudo rm -rf /opt/yachiyo            # 删除项目目录
# 如果是裸机部署:
sudo systemctl disable --now yachiyo-backend yachiyo-frontend
sudo rm /etc/systemd/system/yachiyo-*.service
sudo systemctl daemon-reload
```

或使用一键卸载脚本：

```bash
sudo bash /opt/yachiyo/scripts/deploy-server.sh uninstall
```
