> ⚠️ **以下内容无法自动化，必须由你本人完成。**

| 项目 | 说明 |
|------|------|
| **Linux 服务器** | Arch Linux / Debian 12+ / Ubuntu 22.04+，最低 2C4G，推荐 4C8G |
| **域名**（生产环境） | 用于 HTTPS 和正式访问 |
| **SSL 证书**（生产环境） | Cloudflare 免费证书 / Let's Encrypt / 自签名 |

### 1.3 必须决定的密码/密钥

| 项目 | 说明 | 默认值（不安全） |
|------|------|-----------------|
| **PostgreSQL 密码** | 数据库密码 | `postgres` |
| **JWT Secret Key** | JWT 签名密钥，建议 ≥32 字符随机字符串 | `yachiyo-cpp-secret-key-change-in-production` |
| **Redis 密码** | Redis 访问密码 | 空（无密码） |

生成随机密钥：
```bash
# 生成 JWT Secret
openssl rand -hex 32

# 生成数据库密码
openssl rand -base64 24
```

### 1.4 Live2D 相关（若使用直播功能）

> 详见 `docs/待实现功能清单.md`

1. **模型文件对齐**: `config.yaml` 中 `expression_map` 用英文名（如 `f_smile`），但实际 `.exp3.json` 文件可能是中文名（如 `笑咪咪.exp3.json`）。二选一：
   - 重命名模型文件为英文名
   - 修改 `config.yaml` 中的映射为中文文件名
2. **导出 .motion3.json 文件**: 使用 Live2D Cubism Editor 导出动作文件
3. **SDK 授权确认**: Live2D Cubism SDK for Web 免费版仅限个人非商用

### 1.5 可选服务（按需处理）

| 服务 | 说明 | 需要操作 |
|------|------|---------|
| **GPT-SoVITS** | 语音合成 | 需独立部署 Python 服务，详见 `docs/GPT-SoVITS部署指南.md` |

### 1.6 ⚠️ 已知问题：WebSocket 端口不一致

当前项目存在 WebSocket 端口配置不一致：

| 位置 | WebSocket 端口 |
|------|---------------|
| `docker-compose.yml` | **9001** |
| `backend/.env.example` | **8081** |
| `backend/Dockerfile` EXPOSE | **8081** |
| `nginx.conf` upstream | **8081** |

**建议**：统一为 `9001`（docker-compose 的映射），或统一为 `8081`。部署前请确认并统一修改。

### 1.7 ⚠️ 已知问题：部分服务返回模拟数据

以下后端服务目前返回 mock 数据，尚未真正对接数据库/API：

| 文件 | 说明 |
|------|------|
| `UserService.cpp` | 几乎所有方法返回模拟数据（`暂时返回模拟数据`） |
| `ChatService.cpp` | 聊天记录查询返回模拟数据 |
| `AIServiceImpl.cpp` | AI 对话返回模拟响应，需实现真实 curl 调用 |

这些不影响部署流程本身，但功能不完整。需后续开发完善。

## 3. Docker Compose 部署（推荐）

### 3.1 安装 Docker

**Arch Linux:**
```bash
sudo pacman -S docker docker-compose
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
# 重新登录使组生效
```

**Debian / Ubuntu:**
```bash
# 安装 Docker 官方 GPG key
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/$(. /etc/os-release && echo "$ID")/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# 添加仓库
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/$(. /etc/os-release && echo "$ID") \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
```

### 3.2 克隆项目

```bash
cd /opt
sudo git clone https://github.com/ermaotie6/yachiyoooooooo.git yachiyo
sudo chown -R $USER:$USER /opt/yachiyo
cd /opt/yachiyo
```

### 3.3 配置环境变量

在项目根目录创建 `.env` 文件（Docker Compose 会自动读取）：

```bash
cat > .env << 'EOF'
# ===== 必须修改 =====
JWT_SECRET_KEY=你的随机JWT密钥至少32字符
DEEPSEEK_API_KEY=sk-你的DeepSeek密钥
BAIDU_TRANSLATE_APP_ID=你的百度翻译APPID
BAIDU_TRANSLATE_API_KEY=你的百度翻译密钥

# ===== 可选修改（有默认值） =====
# POSTGRES_PASSWORD=postgres
# POSTGRES_USER=postgres
# POSTGRES_DB=yachiyo
EOF
```

### 3.4 配置后端 config.yaml

编辑 `backend/config/config.yaml`，填入 API Key：

```bash
cd /opt/yachiyo
nano backend/config/config.yaml
```

需要填写的关键字段：
```yaml
ai:
  deepseek:
    api_key: "sk-你的DeepSeek密钥"
    
  translation:
    engines:
      - name: "baidu"
        app_id: "你的百度翻译APPID"
        api_key: "你的百度翻译密钥"
      - name: "deepseek"
        api_key: "sk-你的DeepSeek密钥"  # 复用
  
  deepseek_moderation:
    api_key: "sk-你的DeepSeek密钥"  # 复用

jwt:
  secret: "你的随机JWT密钥至少32字符"

database:
  password: "与docker-compose中POSTGRES_PASSWORD一致"
```

### 3.5 创建 SSL 目录（生产环境）

```bash
mkdir -p /opt/yachiyo/ssl
# 将证书文件放入:
# /opt/yachiyo/ssl/cert.pem
# /opt/yachiyo/ssl/key.pem
```

### 3.6 启动服务

```bash
cd /opt/yachiyo

# 仅启动核心服务（推荐）
docker compose up -d postgres redis backend frontend nginx

# 如需监控工具
docker compose up -d prometheus grafana

# 如需数据库管理工具
docker compose up -d pgadmin redis-commander

# 启动全部服务
docker compose up -d
```

### 3.7 验证部署

```bash
# 检查容器状态
docker compose ps

# 检查后端健康
curl http://localhost:8080/api/v1/health

# 检查前端
curl -I http://localhost:3000

# 查看后端日志
docker compose logs -f backend

# 查看全部日志
docker compose logs -f
```

### 3.8 常用运维命令

```bash
# 停止所有服务
docker compose down

# 停止并清除数据卷（⚠️ 会删除数据库数据）
docker compose down -v

# 重建并启动（代码更新后）
docker compose up -d --build

# 仅重建后端
docker compose up -d --build backend

# 查看数据卷
docker volume ls | grep yachiyo
```

## 4. 一键脚本部署

项目包含自动化部署脚本 `scripts/deploy-server.sh`，支持 Docker 模式和裸机模式。

### 4.1 使用方法

```bash
# 下载并执行（需要 root 或 sudo 权限）
git clone https://github.com/ermaotie6/yachiyoooooooo.git /opt/yachiyo
cd /opt/yachiyo
chmod +x scripts/deploy-server.sh
sudo bash scripts/deploy-server.sh
```

脚本会引导你完成：
1. 检测 Linux 发行版（Arch / Debian / Ubuntu）
2. 选择部署模式（Docker / 裸机）
3. 安装系统依赖
4. 生成 `.env` 配置文件
5. 构建并启动服务
6. 配置 systemd 自启动
7. 配置 Nginx 反向代理
8. 执行健康检查

### 4.2 脚本参数

```bash
# 指定安装目录
INSTALL_DIR=/opt/my-yachiyo bash scripts/deploy-server.sh

# 指定分支
BRANCH=dev bash scripts/deploy-server.sh
```

### 4.3 卸载

```bash
sudo bash scripts/deploy-server.sh --uninstall
```

## 5. 手动裸机部署

> 不使用 Docker，直接在系统上运行。适合开发调试或资源受限的环境。

### 5.1 安装依赖

**Arch Linux:**
```bash
sudo pacman -S base-devel cmake ninja gcc git \
    openssl yaml-cpp postgresql-libs hiredis curl \
    nlohmann-json postgresql redis nginx nodejs npm
```

**Debian / Ubuntu:**
```bash
sudo apt-get update
sudo apt-get install -y build-essential cmake ninja-build gcc g++ git \
    libssl-dev libyaml-cpp-dev libpq-dev libhiredis-dev libcurl4-openssl-dev \
    nlohmann-json3-dev pkg-config \
    postgresql postgresql-contrib redis-server nginx \
    nodejs npm
```

### 5.2 初始化数据库

```bash
# 启动 PostgreSQL
sudo systemctl enable --now postgresql

# 创建数据库
sudo -u postgres psql -c "CREATE DATABASE yachiyo;"
sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '你的数据库密码';"

# 导入初始表结构
sudo -u postgres psql -d yachiyo -f /opt/yachiyo/database/init.sql
```

### 5.3 启动 Redis

```bash
sudo systemctl enable --now redis  # Arch: redis; Debian: redis-server
```

### 5.4 构建后端

```bash
cd /opt/yachiyo/backend
mkdir -p build && cd build
cmake .. -G "Ninja" \
    -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_CXX_STANDARD=20 \
    -DCMAKE_CXX_STANDARD_REQUIRED=ON
ninja
```

构建产物：`/opt/yachiyo/backend/build/yachiyo_cpp`

### 5.5 构建前端

```bash
cd /opt/yachiyo/frontend

# 创建 .env.local
cp .env.example .env.local
# 编辑 .env.local，修改 API 地址为你的服务器地址
nano .env.local

npm ci
npm run build
```

构建产物：`/opt/yachiyo/frontend/dist/`

### 5.6 配置后端

```bash
# 编辑 config.yaml 填入 API Key 和数据库密码
nano /opt/yachiyo/backend/config/config.yaml
```

### 5.7 创建 systemd 服务

**后端服务:**
```bash
sudo tee /etc/systemd/system/yachiyo-backend.service << 'EOF'
[Unit]
Description=Yachiyo Backend Service
After=network.target postgresql.service redis.service

[Service]
Type=simple
User=yachiyo
Group=yachiyo
WorkingDirectory=/opt/yachiyo/backend
ExecStart=/opt/yachiyo/backend/build/yachiyo_cpp --config-dir /opt/yachiyo/backend/config --env production
Restart=always
RestartSec=5
Environment=APP_PORT=8080
Environment=DATABASE_HOST=localhost
Environment=REDIS_URL=redis://localhost:6379

[Install]
WantedBy=multi-user.target
EOF
```

**前端服务:**
```bash
sudo tee /etc/systemd/system/yachiyo-frontend.service << 'EOF'
[Unit]
Description=Yachiyo Frontend Service
After=network.target

[Service]
Type=simple
User=yachiyo
Group=yachiyo
WorkingDirectory=/opt/yachiyo/frontend
ExecStart=/usr/bin/npx serve -s dist -l 3000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
```

**启动服务:**
```bash
# 创建运行用户
sudo useradd -r -s /bin/bash -m yachiyo

# 设置目录权限
sudo chown -R yachiyo:yachiyo /opt/yachiyo

# 启动
sudo systemctl daemon-reload
sudo systemctl enable --now yachiyo-backend
sudo systemctl enable --now yachiyo-frontend
```

### 5.8 配置 Nginx

```bash
# 使用项目自带的 nginx.conf（需修改 upstream 地址为 localhost）
sudo cp /opt/yachiyo/nginx.conf /etc/nginx/nginx.conf

# 或创建站点配置
sudo nano /etc/nginx/nginx.conf
```

修改 `nginx.conf` 中的 upstream，将容器名改为 `localhost`：
```nginx
upstream backend_api {
    server localhost:8080;   # 原: backend:8080
}
upstream frontend_app {
    server localhost:3000;   # 原: frontend:3000
}
upstream websocket_server {
    server localhost:9001;   # 原: backend:8081 → 改为实际监听端口
}
```

```bash
sudo nginx -t  # 测试配置
sudo systemctl enable --now nginx
```

## 6. SSL / HTTPS 配置

### 方案一：Cloudflare（推荐）

1. 将域名 DNS 托管到 Cloudflare
2. 开启 Cloudflare Proxy（橙色云朵）
3. SSL/TLS 模式选择 **Full (Strict)**
4. 在 Cloudflare 生成 Origin Certificate
5. 将证书放入 `/opt/yachiyo/ssl/`：
   ```
   ssl/cert.pem  ← Origin Certificate
   ssl/key.pem   ← Private Key
   ```
6. 取消 `nginx.conf` 中 SSL 相关注释：
   ```nginx
   listen 443 ssl http2;
   ssl_certificate /etc/nginx/ssl/cert.pem;
   ssl_certificate_key /etc/nginx/ssl/key.pem;
   ```

### 方案二：Let's Encrypt

```bash
# 安装 certbot
# Arch:
sudo pacman -S certbot certbot-nginx
# Debian/Ubuntu:
sudo apt-get install -y certbot python3-certbot-nginx

# 获取证书
sudo certbot --nginx -d your-domain.com

# 自动续期
sudo systemctl enable --now certbot-renew.timer
```

### 方案三：自签名证书（仅测试用）

```bash
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /opt/yachiyo/ssl/key.pem \
    -out /opt/yachiyo/ssl/cert.pem \
    -subj "/CN=localhost"
```

## 7. 生产环境安全加固

### 7.1 必做

- [ ] 修改 PostgreSQL 默认密码（不要用 `postgres`）
- [ ] 设置高强度 JWT Secret（≥32 字符随机字符串）
- [ ] 设置 Redis 密码
- [ ] 关闭不必要的端口（5432、6379 不对外暴露）
- [ ] 修改 `config.yaml` 中 `cors_origins` 为实际域名（不要用 `*`）
- [ ] 修改 `database/init.sql` 中管理员账户密码哈希

### 7.2 建议

- [ ] 启用 HTTPS（见第 6 节）
- [ ] 配置防火墙（ufw / firewalld / iptables）
- [ ] 关闭 pgAdmin 和 Redis Commander 的外部访问（或不启动）
- [ ] 将 Grafana 默认密码从 `admin` 修改为强密码
- [ ] 配置日志轮转
- [ ] 定期备份数据库

### 7.3 防火墙示例

```bash
# UFW (Debian/Ubuntu)
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp    # SSH
sudo ufw allow 80/tcp    # HTTP
sudo ufw allow 443/tcp   # HTTPS
sudo ufw enable

# firewalld (Arch)
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --reload
```

## 9. 常见问题

### Q: 后端启动失败，提示数据库连接错误

**A:** 检查以下几点：
1. PostgreSQL 是否已启动：`docker compose ps postgres` 或 `systemctl status postgresql`
2. `config.yaml` 中数据库密码是否与 `docker-compose.yml` 中一致
3. Docker 模式下 `database.host` 应为 `postgres`（容器名），裸机模式下应为 `localhost`

### Q: 前端页面加载但无法调用 API

**A:** 检查前端环境变量：
- Docker 模式：`docker-compose.yml` 中 `VITE_API_BASE_URL` 是否正确
- 裸机模式：`frontend/.env.local` 中 `VITE_API_BASE_URL` 是否指向后端地址
- 检查 Nginx 是否正确代理 `/api/v1/` 到后端

### Q: WebSocket 连接失败

**A:** 
1. 确认 WebSocket 端口配置统一（见 1.6 节）
2. 检查 Nginx 中 WebSocket 代理配置（`/ws` 路径）
3. 如使用 Cloudflare，需在 Network 设置中启用 WebSockets

### Q: Docker 构建后端很慢 / 失败

**A:**
- 后端 C++ 编译需要较多内存，确保服务器 ≥4GB RAM
- 如果 OOM，尝试 `docker compose build --no-cache backend`
- 可以在本地构建好镜像后推送到 Docker Registry

### Q: 如何修改默认管理员账号

**A:** 编辑 `database/init.sql` 最底部的 INSERT 语句，修改用户名和密码哈希。注意初始密码哈希是占位符 `$2b$12$placeholder_hash_admin_user`，你需要在首次登录后修改密码，或直接生成正确的 bcrypt 哈希替换。

```
1. [ ] 准备 Linux 服务器（2C4G 起步）
2. [ ] 获取 DeepSeek API Key
3. [ ] 获取百度翻译 APP ID + API Key
4. [ ] 克隆项目到服务器
5. [ ] 创建 .env 文件，填入 JWT Secret + API Keys
6. [ ] 编辑 backend/config/config.yaml，填入 API Keys
7. [ ] 统一 WebSocket 端口配置
8. [ ] docker compose up -d
9. [ ] 验证 http://服务器IP:80 可访问
10.[ ] 配置域名 + SSL（生产环境）
11.[ ] 修改默认密码（PostgreSQL、Grafana、pgAdmin）
12.[ ] 配置防火墙，关闭不必要端口
```
