# Yachiyo 部署指南

> **版本**: v4.1.0  
> **更新**: 2026年4月  
> **适用系统**: Arch Linux / Debian / Ubuntu  
> **部署方式**: 分阶段脚本部署（主推）/ Docker Compose / 裸机部署  
> **配置键路径**: 已与 `Application.cpp` 代码完全对齐

---

## 总览：部署分为 7 个阶段

每个阶段都有对应的**独立脚本**（位于 `scripts/deploy/` 目录），可以单独执行和重试。全流程也可以用编排脚本 `deploy-all.sh` 或一键脚本 `deploy-server.sh` 串联完成。

```text
阶段 1 → 阶段 2 → 阶段 3 → 阶段 4 → 阶段 5 → 阶段 6 → 阶段 7
系统准备   环境安装   代码部署   密钥配置   构建启动   验证测试   HTTPS+加固
```

| 阶段 | 脚本路径 | 说明 | 耗时 |
| --- | --- | --- | --- |
| 1. 系统准备 | `scripts/deploy/stage1-prepare.sh` | 检查硬件、更新系统、配置防火墙 | ~2 分钟 |
| 2. 环境安装 | `scripts/deploy/stage2-install.sh` | 安装 Docker / Docker Compose | ~3 分钟 |
| 3. 代码部署 | `scripts/deploy/stage3-code.sh` | 克隆/更新项目代码 | ~1 分钟 |
| 4. 密钥配置 | `scripts/deploy/stage4-config.sh` | 生成 .env + 交互式填写密钥 | ~2 分钟 |
| 5. 构建启动 | `scripts/deploy/stage5-build.sh` | 编译后端 + 构建前端 + 启动全部 | ~10 分钟 |
| 6. 验证测试 | `scripts/deploy/stage6-verify.sh` | 健康检查 + 功能验证 | ~1 分钟 |
| 7. HTTPS 加固 | `scripts/deploy/stage7-secure.sh` | 证书部署 + Nginx SSL + 安全加固 | ~3 分钟 |

另外还有：

| 脚本 | 用途 |
| --- | --- |
| `scripts/deploy/deploy-all.sh` | 串联执行阶段 1~6（支持 `--from N` / `--only N`） |
| `scripts/deploy-server.sh` | 原有一键部署脚本（docker/native/uninstall） |
| `scripts/update.sh` | 拉取代码 + 重建 + 健康检查 |
| `scripts/start.sh` | 启动服务 |
| `scripts/stop.sh` | 停止服务 |

## 1. 硬件与系统要求

### 硬件要求

| 规格 | 最低 | 推荐 | 说明 |
| --- | --- | --- | --- |
| CPU | 2 核 | 4 核 | C++ 编译需要较多 CPU |
| 内存 | 4 GB | 8 GB | Docker 编译后端时内存占用高 |
| 硬盘 | 20 GB SSD | 50 GB SSD | Docker 镜像 + 数据库 + 日志 |
| GPU | 不需要 | 不需要 | 仅 GPT-SoVITS 需要 NVIDIA GPU |

### 操作系统

支持 Arch Linux / Debian 12+ / Ubuntu 22.04+。脚本会自动检测发行版并使用对应的包管理器。

### 防火墙端口

只需对外开放 3 个端口：

| 端口 | 用途 |
| --- | --- |
| 22 | SSH |
| 80 | HTTP（重定向到 HTTPS） |
| 443 | HTTPS |

> 其他端口（8080/9001/3000/5432/6379 等）全部走内网，由 Nginx 反向代理，**不对外暴露**。

### 需要提前准备的东西

在开始部署之前，确保你已经拿到了以下信息：

| 项目 | 获取方式 | 必须? |
| --- | --- | --- |
| DeepSeek API Key | https://platform.deepseek.com/api_keys | ✅ 必须 |
| 百度翻译 APPID + 密钥 | https://fanyi-api.baidu.com/manage/developer | ✅ 必须 |
| Cloudflare Origin Certificate | Cloudflare → SSL/TLS → Origin Server | ⬜ 上 HTTPS 时需要 |
| OpenClaw 服务地址 | 自行部署或找服务提供商 | ⬜ 可选 |

## 2. 一键部署（推荐）

### 方法 A：全流程编排脚本（推荐）

先克隆项目，然后用 `deploy-all.sh` 串联执行阶段 1~6：

```bash
git clone https://github.com/ermaotie6/yachiyoooooooo.git /opt/yachiyo
cd /opt/yachiyo
chmod +x scripts/deploy/*.sh
sudo bash scripts/deploy/deploy-all.sh
```

支持从指定阶段开始（比如阶段 4 失败了，修复后从 4 继续）：

```bash
sudo bash scripts/deploy/deploy-all.sh --from 4
```

只执行某个阶段：

```bash
sudo bash scripts/deploy/deploy-all.sh --only 6
```

### 方法 B：原有一键脚本

```bash
git clone https://github.com/ermaotie6/yachiyoooooooo.git /opt/yachiyo
cd /opt/yachiyo
chmod +x scripts/deploy-server.sh
sudo bash scripts/deploy-server.sh docker
```

一键脚本 `deploy-server.sh` 内部会自动：检测发行版 → 安装 Docker → 克隆代码 → 生成 `.env` → 构建启动 → 健康检查。

> ⚠️ 两种方式执行完后，都需要手动编辑 `.env` 填入 API 密钥，然后重启服务使配置生效。

**如果想要更精细的控制**，请按下面的分阶段操作。

## 3. 阶段 1：系统准备

> **目标**：确认服务器满足要求，更新系统，配置防火墙。  
> **脚本**：`scripts/deploy/stage1-prepare.sh`

### 执行

```bash
sudo bash scripts/deploy/stage1-prepare.sh
```

### 脚本做了什么

1. **检查 root 权限**
2. **检测发行版**：自动识别 Arch/Debian/Ubuntu 系列
3. **硬件检查**：CPU ≥ 2核、内存 ≥ 4GB、磁盘 ≥ 15GB，不满足会警告
4. **更新系统包**：`pacman -Syu` 或 `apt-get update && upgrade`
5. **安装基础工具**：git, curl, wget, openssl, ca-certificates 等
6. **配置防火墙**：
   - Debian/Ubuntu: UFW，开放 22/80/443
   - Arch: iptables，开放 22/80/443

### 手动等效操作

<details>
<summary>点击展开手动命令</summary>

```bash
# Arch Linux
sudo pacman -Syu
sudo pacman -S base-devel git curl wget openssl ca-certificates

# Debian / Ubuntu
sudo apt-get update && sudo apt-get upgrade -y
sudo apt-get install -y build-essential git curl wget openssl ca-certificates gnupg lsb-release

# 防火墙 (Debian/Ubuntu)
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

</details>

## 4. 阶段 2：环境安装

> **目标**：安装 Docker 和 Docker Compose。  
> **脚本**：`scripts/deploy/stage2-install.sh`

### 执行

```bash
sudo bash scripts/deploy/stage2-install.sh
```

### 脚本做了什么

1. **安装 Docker**：
   - Arch: `pacman -S docker docker-compose docker-buildx`
   - Debian/Ubuntu: 添加 Docker 官方 GPG + APT 源，安装 docker-ce 全家桶
2. **启动 Docker 服务**：`systemctl enable --now docker`
3. **加入 docker 组**：避免每次 sudo
4. **验证 Docker Compose**：自动检测 v2 插件或独立版

### 验证

```bash
docker --version          # Docker Engine 24+ 即可
docker compose version    # Docker Compose v2.20+ 即可
```

## 6. 阶段 4：密钥配置

> **目标**：生成 `.env` 文件，填入所有 API 密钥。  
> **脚本**：`scripts/deploy/stage4-config.sh`

这是**唯一需要人工干预**的阶段——你需要填入自己的 API 密钥。

### 执行

```bash
sudo bash scripts/deploy/stage4-config.sh
```

### 交互流程

脚本会提示你输入：

```text
  DeepSeek API Key (sk-开头): sk-xxxxx
  百度翻译 APPID (纯数字): 20150630000000001
  百度翻译密钥 (字母数字): abc1234567890
  数据库密码 (默认 postgres): [直接回车用默认]
```

- **JWT 密钥**：自动生成 64 字符随机字符串，无需手动填
- **直接回车**可跳过，稍后用 `nano /opt/yachiyo/.env` 补充
- 如果 `.env` 已存在，会询问是否覆盖（覆盖前自动备份）

### 关于百度翻译 APPID

百度翻译开放平台 "开发者信息" 页面 (https://fanyi-api.baidu.com/manage/developer) 上只有两个东西：

- **APPID**：一串数字，如 `20150630000000001`
- **密钥**：一串字母数字，如 `abc1234567890`

> 没有所谓的 "APP ID"。就是 **APPID**（一个词，没有空格），页面上直接叫这个名字。

## 7. 阶段 5：构建启动

> **目标**：编译 C++ 后端，构建 Vue 前端，启动所有 Docker 容器。  
> **脚本**：`scripts/deploy/stage5-build.sh`

### 执行

```bash
sudo bash scripts/deploy/stage5-build.sh
```

### 脚本做了什么

分 4 步依序启动：

| 步骤 | 操作 | 等待条件 |
| --- | --- | --- |
| 1/4 | `docker compose up -d postgres redis` | `pg_isready` + `redis-cli ping` |
| 2/4 | `docker compose up -d --build backend` | `curl /api/v1/health` 返回 200 |
| 3/4 | `docker compose up -d --build frontend` | `curl localhost:3000` 返回 200 |
| 4/4 | `docker compose up -d nginx bridge` | `curl localhost` 返回 200 |

> 首次构建 C++ 后端需要 **5~15 分钟**。可在另一个终端用 `docker compose logs -f backend` 查看编译进度。

### 如果编译 OOM

C++ 编译消耗大量内存。如果 OOM（被 killed），可以限制并行编译数：

```bash
docker compose build --build-arg CMAKE_BUILD_PARALLEL_LEVEL=2 backend
docker compose up -d backend
```

## 8. 阶段 6：验证测试

> **目标**：验证每个服务是否正常运行。  
> **脚本**：`scripts/deploy/stage6-verify.sh`

### 执行

```bash
sudo bash scripts/deploy/stage6-verify.sh
```

### 7 项自动化测试

| 测试 | 检查内容 | 判定标准 |
| --- | --- | --- |
| 1. 容器状态 | postgres/redis/backend/frontend/nginx | 全部 Up |
| 2. 后端 API | `GET /api/v1/health` | 返回 200 |
| 3. 前端服务 | `GET localhost:3000` | 返回 200 |
| 4. Nginx 代理 | `GET localhost/` + `GET localhost/api/v1/health` | 返回 200/301 |
| 5. 数据库连接 | 查询 public schema 表数量 | > 5 张表 |
| 6. Redis 缓存 | `redis-cli ping` | 返回 PONG |
| 7. WebSocket | 检查容器内 9001 端口 | 端口监听中 |

输出示例：

## 9. 阶段 7：HTTPS 与安全加固

> **目标**：部署 SSL 证书，启用 HTTPS，执行安全加固。  
> **脚本**：`scripts/deploy/stage7-secure.sh`

### 前提

你需要 Cloudflare Origin Certificate。如果还没有：
1. 登录 Cloudflare → 选择域名 → SSL/TLS → Origin Server
2. 点击 "Create Certificate"
3. 保存 Certificate (cert.pem) 和 Private Key (key.pem)

### 执行

```bash
sudo bash scripts/deploy/stage7-secure.sh
```

### 交互流程

**步骤 1 — SSL 证书部署**：脚本提供 3 种方式：
1. 手动粘贴证书内容（粘贴后输入 `EOF` 结束）
2. 从本地路径复制
3. 跳过 HTTPS

**步骤 2 — Nginx SSL 配置**：提示你编辑 `nginx.conf` 取消 SSL 相关注释，然后自动重启 Nginx。

**步骤 3 — 安全加固检查表**（5 项自动检测）：
- JWT 密钥长度 ≥ 32
- 数据库密码不是默认值
- CORS 不是 `*`
- pgAdmin / Redis Commander 未暴露
- `.env` 文件权限为 600

## 10. 裸机部署（不用 Docker）

如果不想用 Docker，可以直接在服务器上编译运行。适合轻量服务器或者不方便装 Docker 的情况。

### 一键裸机部署脚本

```bash
cd /opt/yachiyo
sudo bash scripts/deploy-server.sh native
```

这个脚本会自动：
1. 安装 C++ 编译工具链 + Node.js + PostgreSQL + Redis
2. 编译 C++ 后端（CMake + Ninja）
3. 构建 Vue 前端（npm ci + npm run build）
4. 创建 systemd 服务（自动启停、开机自启、崩溃重启）
5. 配置 Nginx 反向代理
6. 部署前端静态文件到 `/var/www/yachiyo`

### 手动裸机部署步骤

<details>
<summary>点击展开完整手动步骤</summary>

#### 10.1 安装系统依赖

**Arch Linux:**

```bash
sudo pacman -S base-devel cmake ninja gcc git \
    openssl yaml-cpp postgresql-libs libpqxx hiredis curl \
    nlohmann-json postgresql redis nginx nodejs npm
```

**Debian / Ubuntu:**

```bash
sudo apt-get install -y build-essential cmake ninja-build gcc g++ git \
    libssl-dev libyaml-cpp-dev libpq-dev libhiredis-dev libcurl4-openssl-dev \
    nlohmann-json3-dev pkg-config uuid-dev \
    postgresql postgresql-contrib redis-server nginx nodejs npm
```

#### 10.2 初始化数据库

```bash
sudo systemctl enable --now postgresql
sudo -u postgres psql -c "CREATE DATABASE yachiyo;"
sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '你的数据库密码';"
sudo -u postgres psql -d yachiyo -f /opt/yachiyo/database/init.sql
```

#### 10.3 编译后端

```bash
cd /opt/yachiyo/backend
mkdir -p build && cd build
cmake .. -G "Ninja" -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_STANDARD=20
ninja -j$(nproc)
```

#### 10.4 构建前端

```bash
cd /opt/yachiyo/frontend
npm ci
npm run build
```

#### 10.5 创建 systemd 服务

```bash
# 创建专用用户
sudo useradd -r -s /usr/sbin/nologin -d /opt/yachiyo yachiyo
sudo chown -R yachiyo:yachiyo /opt/yachiyo

# 后端服务
sudo tee /etc/systemd/system/yachiyo-backend.service << 'EOF'
[Unit]
Description=Yachiyo Backend Server
After=network.target postgresql.service redis.service
Wants=postgresql.service redis.service

[Service]
Type=simple
User=yachiyo
Group=yachiyo
WorkingDirectory=/opt/yachiyo/backend
ExecStart=/opt/yachiyo/backend/build/yachiyo_cpp --config-dir /opt/yachiyo/backend/config --env production
Restart=always
RestartSec=5
EnvironmentFile=/opt/yachiyo/.env
Environment=DB_HOST=localhost
Environment=REDIS_HOST=localhost

# 安全加固
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/opt/yachiyo/logs /opt/yachiyo/backend/logs /tmp
PrivateTmp=true

[Install]
WantedBy=multi-user.target
EOF

# 前端服务
sudo tee /etc/systemd/system/yachiyo-frontend.service << 'EOF'
[Unit]
Description=Yachiyo Frontend (serve)
After=network.target

[Service]
Type=simple
User=yachiyo
Group=yachiyo
WorkingDirectory=/opt/yachiyo/frontend
ExecStart=/usr/bin/npx serve -s dist -l 3000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now yachiyo-backend yachiyo-frontend
```

#### 10.6 配置 Nginx

```bash
# 部署前端静态文件
sudo mkdir -p /var/www/yachiyo
sudo cp -r /opt/yachiyo/frontend/dist/* /var/www/yachiyo/

# 生成 Nginx 配置（将 Docker 容器名替换为 localhost）
sudo cp /opt/yachiyo/nginx.conf /etc/nginx/nginx.conf
sudo sed -i 's/server backend:8080/server 127.0.0.1:8080/g' /etc/nginx/nginx.conf
sudo sed -i 's/server backend:9001/server 127.0.0.1:9001/g' /etc/nginx/nginx.conf
sudo sed -i 's/server frontend:3000/server 127.0.0.1:3000/g' /etc/nginx/nginx.conf

# 测试并启动
sudo nginx -t && sudo systemctl enable --now nginx
```

</details>

## 11. GPT-SoVITS 语音合成（可选）

GPT-SoVITS 是独立的 Python 服务，用于生成虚拟形象的语音。

### 硬件要求

**必须要 NVIDIA 独立显卡。Intel 核显不能用。**

原因：GPT-SoVITS 依赖 PyTorch CUDA 加速。Intel 核显（UHD/Iris）没有 CUDA 支持，PyTorch 无法将其识别为 GPU 设备。

| 方案 | 说明 |
| --- | --- |
| 有 NVIDIA GPU | 正常部署，详见 `docs/GPT-SoVITS部署指南.md` |
| 没有 GPU | 设置 `gpt_sovits.enabled: false` 禁用语音，AI 只输出文字 |
| 想要语音但没本地 GPU | 租一台 GPU 云服务器（AutoDL/RunPod），部署 GPT-SoVITS，通过 HTTP 调用 |
| CPU 推理 | 技术上可以，但每条语音 5~30 秒，不适合实时直播 |

### 快速对接

如果已部署好 GPT-SoVITS API，只需修改配置：

```yaml
# 编辑 backend/config/config.yaml
gpt_sovits:
  enabled: true
  api_endpoint: "http://GPU服务器地址:5000"
  mode: "gpu"           # 或 "cpu"
  timeout_seconds: 15   # GPU 模式可以设低
```

详细安装流程见 `docs/GPT-SoVITS部署指南.md`。

## 12. 日常运维脚本

部署完成后，日常运维可以使用项目自带的脚本或直接 Docker Compose 命令。

### 更新部署

```bash
# 使用更新脚本 (拉取代码 + 重建 + 健康检查)
sudo bash scripts/update.sh              # 重建 backend + frontend
sudo bash scripts/update.sh backend      # 只重建后端
sudo bash scripts/update.sh frontend     # 只重建前端
```

### 快速参考

```bash
cd /opt/yachiyo

# ===== 查看状态 =====
docker compose ps                                    # 查看所有容器
docker compose logs -f backend                       # 实时查看后端日志
docker compose logs -f --tail 100 backend bridge     # 同时看后端和桥接日志

# ===== 启停 =====
docker compose stop                                  # 停止所有
docker compose start                                 # 启动所有
docker compose restart backend                       # 重启后端
docker compose down                                  # 停止并移除容器 (数据卷保留)

# ===== 数据库 =====
# 备份
docker compose exec postgres pg_dump -U postgres yachiyo > backup_$(date +%Y%m%d).sql
# 恢复
docker compose exec -T postgres psql -U postgres yachiyo < backup_20260408.sql
# 进入 psql 交互
docker compose exec postgres psql -U postgres yachiyo

# ===== 监控工具 (可选启停) =====
docker compose up -d prometheus grafana              # 启动监控
docker compose up -d pgadmin                         # 启动 pgAdmin (http://localhost:5050)
docker compose stop pgadmin redis-commander          # 关闭管理工具 (生产推荐)

# ===== 清理 =====
docker system prune -f                               # 清理无用的镜像和容器
docker volume prune -f                               # 清理无用的数据卷 (⚠️ 小心!)
```

### 重新验证部署

随时可以重新跑验证脚本检查服务状态：

```bash
sudo bash scripts/deploy/stage6-verify.sh
```

## 13. 常见问题

### Q: 后端连不上数据库

```bash
# 1. 检查 PostgreSQL 是否运行
docker compose ps postgres
# 2. 检查密码是否一致
grep DATABASE_PASSWORD .env
grep password backend/config/config.yaml
# 3. Docker 模式下 host 是 postgres (容器名)，裸机是 localhost
```

### Q: 前端无法调用 API

```bash
# 1. 检查 Nginx 是否正确代理了 /api 路径
curl -I http://localhost/api/v1/health
# 2. 检查 Nginx 日志
docker compose logs nginx
```

### Q: WebSocket 连接失败

1. Nginx 中 `/ws` 路径是否有 WebSocket 升级头配置 — 项目自带的 `nginx.conf` 已配置好
2. Cloudflare → Network → WebSockets 是否已开启（免费版默认开启）
3. 前端是否使用了 `wss://` 协议（走 Cloudflare 必须 HTTPS）

### Q: Docker 构建后端很慢 / OOM

```bash
# 限制并行编译数 (降低内存占用)
docker compose build --build-arg CMAKE_BUILD_PARALLEL_LEVEL=2 backend

# 查看内存使用
docker stats --no-stream

# 如果反复 OOM，考虑增加 swap
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

### Q: Cloudflare 报 522/524 错误

- **522 (Connection Timed Out)**: 服务器不可达 → 检查防火墙是否开放了 80/443
- **524 (A Timeout Occurred)**: 请求超时 → 检查 Nginx 和后端是否在运行

```bash
# 快速诊断
sudo ufw status                    # 防火墙规则
docker compose ps                  # 容器状态
curl -I http://localhost           # 本地是否正常
```

### Q: 百度翻译报 54001 签名错误

检查 APPID 和密钥是否正确填入。APPID 是纯数字，密钥是字母数字组合。两个值在百度翻译开放平台 → 开发者信息页面获取。

```bash
# 验证 .env 中的值
grep BAIDU .env
```

### Q: 如何从某个阶段重新开始？

每个阶段脚本都是幂等的（可重复执行），直接重新运行对应的阶段脚本即可：

```bash
sudo bash scripts/deploy/stage4-config.sh    # 重新配置密钥
sudo bash scripts/deploy/stage5-build.sh     # 重新构建启动
sudo bash scripts/deploy/stage6-verify.sh    # 重新验证
```

或者使用编排脚本从指定阶段继续：

```bash
sudo bash scripts/deploy/deploy-all.sh --from 4
```

### Q: 如何完全卸载？

```bash
cd /opt/yachiyo
docker compose down -v              # 停止容器并删除数据卷
cd /
sudo rm -rf /opt/yachiyo            # 删除项目目录
# 如果是裸机部署:
sudo systemctl disable --now yachiyo-backend yachiyo-frontend
sudo rm /etc/systemd/system/yachiyo-*.service
sudo systemctl daemon-reload
```

或使用一键卸载脚本：

```bash
sudo bash /opt/yachiyo/scripts/deploy-server.sh uninstall
```
