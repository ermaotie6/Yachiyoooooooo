## 一、系统总览

Yachiyo 是一个 **AI 虚拟形象直播平台**，核心目标是让用户通过文字/语音与一个 Live2D 虚拟角色实时交互。系统由以下组件组成：

```
┌─────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   浏览器     │────▶│  Nginx (:80) │────▶│  前端 (:3000) │     │  OpenClaw    │
│  (用户端)    │     │  反向代理     │     │  Vue 3 + TS   │     │  (:8000)     │
└──────┬──────┘     └──────┬───────┘     └──────────────┘     └──────▲───────┘
       │                   │                                         │

│                                          │────▶│  Bridge (:8765)
│  :8080  HTTP API                         │     │  Node.js 桥接

## 二、启动流程

### 2.1 应用程序生命周期 (`main.cpp` → `Application.cpp`)

```
程序启动
  │
  ├─ globalInit()                      # __attribute__((constructor))
  │   ├─ setupGlobalExceptionHandler() # std::set_terminate
  │   └─ setupSignalHandlers()         # SIGINT, SIGTERM, SIGSEGV, SIGABRT
  │
  ├─ Application::getInstance()        # 单例模式
  │
  ├─ Application::initialize()
  │   ├─ parseArguments()              # --config-dir, --env, --port, --host, --workers
  │   ├─ ConfigManager::initialize()   # 加载 config/config.yaml
  │   ├─ LogUtils::initialize()        # spdlog 日志系统
  │   ├─ initializeHttpServer()        # Crow HTTP 服务器
  │   │   ├─ 配置 SSL (可选)
  │   │   ├─ 配置 CORS
  │   │   ├─ 配置压缩
  │   │   └─ 配置速率限制
  │   ├─ initializeDatabase()          # PostgreSQL 连接池 (pqxx)
  │   ├─ initializeAIServices()        # AI 提供商配置
  │   ├─ initializeServices()
  │   │   ├─ WebSocketService          # 独立线程, :9001
  │   │   └─ Redis 连接池 (可选)
  │   └─ initializeControllers()       # 注册所有路由 (详见下方)
  │
  ├─ Application::start()              # httpServer->start()
  │
  └─ Application::wait()               # 阻塞等待，直到收到停止信号
```

```

**前端 Token 管理** (`stores/auth.ts`):
- `accessToken` + `refreshToken` 存储在 `localStorage` + Pinia
- Axios 请求拦截器自动附加 `Authorization: Bearer <token>`
- 响应拦截器检测 401 → 自动调用 `/auth/refresh` → 重试原始请求
- 访问需认证页面时未登录 → 路由守卫重定向到首页并自动弹出登录对话框 (`showLogin=true`)

### 3.4 消息审查流程 (6层安全系统)

用户在直播间发送的每条消息都经过 6 层安全审查：

```
用户发送消息
     │
     ▼
┌─── 第1层: 速率限制 ──────────────────────────────────┐
│  Redis 计数器: rate_limit:{userId}                    │
│  限制: 10条/分钟, 100条/小时                          │
│  超限 → 返回 "消息过于频繁，请稍后再试"              │
└───────────────────────┬──────────────────────────────┘
                        │ 通过
                        ▼
┌─── 第2层: IP检查 ────────────────────────────────────┐
│  检查发送者 IP 是否在黑名单中                         │
│  命中 → 返回 "您的IP已被限制"                        │
└───────────────────────┬──────────────────────────────┘
                        │ 通过
                        ▼
┌─── 第3层: 关键词过滤 ────────────────────────────────┐
│  多级敏感词库匹配                                     │
│  命中高危词 → 标记 isBlockedKeyword=true              │
│  计算 keywordScore (0.0-1.0)                         │
└───────────────────────┬──────────────────────────────┘
                        │ 通过
                        ▼
┌─── 第4层: AI内容审查 ────────────────────────────────┐
│  语义分析: 检测变体词、谐音、隐含含义                 │
│  命中 → 标记 isAbusive=true, 计算 aiScore            │
└───────────────────────┬──────────────────────────────┘
                        │ 通过
                        ▼
┌─── 第5层: 行为分析 ──────────────────────────────────┐
│  ① 5分钟消息频率 (Redis user_activity:{userId})      │
│  ② 24小时内多IP检测 (SQL查询)                        │
│  ③ 同IP被拒消息数检测                                │
│  异常 → 标记 hasAbnormalBehavior=true                │
└───────────────────────┬──────────────────────────────┘
                        │ 通过
                        ▼
┌─── 第6层: 综合评分 → 决定审查级别 ───────────────────┐
│  spamScore > 0.6 → ReviewStatus::REJECTED            │
│  spamScore > 0.3 → ReviewStatus::PENDING_REVIEW      │
│  spamScore ≤ 0.3 → ReviewStatus::APPROVED            │
│                                                       │
│  写入 PostgreSQL (messages 表)                        │
│  返回消息对象 (含 review_status, spam_score)          │
└──────────────────────────────────────────────────────┘
```

### 3.5 Bridge 桥接服务流程

Bridge 是一个无状态的 Node.js HTTP 代理，唯一职责是中转 C++ 后端与 OpenClaw 之间的通信：

```
C++ 后端 (OpenClawGateway)
     │
     │  POST http://bridge:8765/process
     │  {
     │    "request_id": "uuid",
     │    "user_id": "user123",
     │    "text": "你好",
     │    "context": "...",
     │    "emotion_hints": ["开心"],
     │    "max_tokens": 1000,
     │    "temperature": 0.7
     │  }
     │
     ▼
Bridge (Node.js Express :8765)
     │
     │  axios.post("http://openclaw:8000/process", 原始请求体)
     │  添加 Authorization header (如果配置了 API Key)
     │  超时: 30s
     │
     ▼
OpenClaw (:8000)
     │
     │  AI 推理 (生成文本 + 情感 + 动作)
     │
     ▼
Bridge
     │
     │  组装标准响应:
     │  {
     │    "request_id": "uuid",
     │    "success": true,
     │    "text": "AI回复文本",
     │    "emotions": ["happy", "excited"],
     │    "actions": ["wave", "nod"],
     │    "processing_time_ms": 1200
     │  }
     │
     ▼
C++ 后端 → 继续 AvatarResponseService 后续步骤
```

## 七、关键技术决策

| 决策 | 选型 | 原因 |
|------|------|------|
| 后端框架 | Crow (C++) | 高性能 HTTP/WebSocket 框架，适合实时场景 |
| 前端框架 | Vue 3 + TypeScript | 组合式 API，良好的 TypeScript 支持 |
| Live2D | pixi-live2d-display | 基于 PixiJS 的 Live2D 渲染，浏览器原生支持 |
| TTS | GPT-SoVITS | 开源高质量语音合成，支持情感控制和声音克隆 |
| AI 对话 | OpenClaw (通过 Bridge) | 独立 AI 服务，通过 Node.js 桥接解耦 |
| 内容审核 | DeepSeek API | 利用大模型做语义级内容安全审查 |
| 翻译 | 百度翻译 + DeepSeek | 双引擎自动降级，保证可用性 |
| 数据库 | PostgreSQL + pqxx | 可靠的关系型数据库，C++ 原生驱动 |
| 缓存 | Redis + hiredis | 速率限制/Token 黑名单/翻译&TTS 缓存 |
| 实时通信 | WebSocket (Crow) | 低延迟双向通信，推送 Avatar 响应 |
| 嘴部同步 | Web Audio API (AnalyserNode) | 前端实时分析音频频率驱动 ParamMouthOpenY |
| 命名空间 | Yachiyo:: + yachiyo:: + Compat.hpp | 历史遗留双大小写，通过别名桥接 |

## 八、一次完整交互的时间线

以用户在直播间发送 "你好，八千代！" 为例：

```
T+0ms     用户在 LiveStream.vue 输入框按下"发送"
T+1ms     useWebSocket.sendUserMessage("你好，八千代！")
T+2ms     WebSocket 消息发送到 C++ 后端 :9001
T+3ms     WebSocketController.processUserMessage() 开始
T+5ms     ── AvatarResponseService.processUserMessage() ──
T+10ms    [步骤1] DeepSeekModerationService.moderate() → "pass"
T+50ms    [步骤2] OpenClawGateway → Bridge :8765 → OpenClaw :8000
T+800ms   OpenClaw 返回: text="你好呀！见到你很高兴~" emotions=["happy"] actions=["wave"]
T+810ms   [步骤3] TranslationService (目标语言=ja → 百度翻译为日语)
T+820ms   [步骤4] GPTSoVITSService.synthesizeWithEmotion("你好呀！...", "happy", DEFAULT)
T+2500ms  TTS 返回: audioUrl, durationMs=2800
T+2510ms  [步骤5] Live2DAnimationService.generateAnimationSequence(["happy"], ["wave"])
T+2520ms  [步骤6] generateMouthSyncCommands(audioUrl, 2800ms)
T+2530ms  [步骤7] 组装 AvatarResponse, processingTimeMs=2525
T+2535ms  ── WebSocketService 推送 JSON 到前端 ──
T+2540ms  前端收到 AvatarResponse
T+2542ms  ① 显示文本 "你好呀！见到你很高兴~" + 情感标签 "happy"
T+2543ms  ② 字幕覆盖层显示: subtitleText = "你好呀！见到你很高兴~"
T+2545ms  ③ Live2DComponent 执行: 表情→smile + 动作→wave
T+2550ms  ④ audioPlayer.play(audioUrl) 开始播放语音
T+2555ms  ⑤ AudioAnalyser 开始实时计算 mouthOpenY → 驱动嘴部动画
T+5350ms  ⑥ 音频播放结束, 嘴巴闭合, 恢复待机表情, 字幕清除
```

**端到端延迟**: ~2.5s (主要瓶颈: TTS 语音合成 ~1.7s)
