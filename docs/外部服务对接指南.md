## OpenClaw 对接

### 架构概述

Yachiyo 后端通过 **Node.js 桥接服务** 与 OpenClaw 通信，采用 **纯同步 HTTP JSON** 模式：

```
┌─────────────┐     HTTP POST      ┌─────────────────┐     转发       ┌────────────────┐
│  C++ 后端   │ ──── JSON ────→   │ Bridge (Node.js) │ ── JSON ──→   │ OpenClaw (:8000)│
│ (Yachiyo)   │ ←── JSON ────     │    (:8765)       │ ←─ JSON ──    │                │
└─────────────┘                   └─────────────────┘                └────────────────┘
```

### 通信协议

**请求**: C++ 后端向桥接服务 `http://localhost:8765/process` 发送 HTTP POST，Body 为 JSON：

```json
{
    "requestId": "uuid-string",
    "userId": "user_123",
    "text": "你好，Yachiyo",
    "context": "可选的对话上下文",
    "emotions": ["happy"],
    "timestamp": 1700000000
}
```

**响应**: 桥接服务同步转发 OpenClaw 的结果并返回 JSON：

```json
{
    "requestId": "uuid-string",
    "success": true,
    "text": "你好！我是 Yachiyo，很高兴见到你！",
    "emotions": ["happy", "excited"],
    "actions": ["wave", "smile"],
    "metadata": {
        "model": "openclaw-v1",
        "processingTimeMs": 350
    },
    "error": ""
}
```

### 相关代码

| 文件 | 说明 |
|------|------|
| `include/services/OpenClawGateway.hpp` | 网关接口和实现 |
| `src/services/OpenClawGateway.cpp` | 网关实现（HTTP POST + JSON 解析） |
| `include/dto/OpenClawDTO.hpp` | OpenClaw 请求/响应 DTO |
| `bridge/src/index.js` | Node.js 桥接服务（Express, 端口 8765） |

### 桥接服务说明

桥接服务 (`bridge/`) 是一个无状态 HTTP 代理：
- **无会话管理** — 每个请求独立处理
- **无异步回调** — 同步转发，等待 OpenClaw 响应后返回
- **超时控制** — 默认 30 秒超时
- **健康检查** — `GET /health` 端点

### 配置

在 `config/config.yaml` 中无需配置 OpenClaw API Key（密钥由 OpenClaw 服务端管理）。
只需配置桥接服务地址：

```yaml
# config/config.yaml 中无显式 openclaw 段落时，默认值为:
# bridge_endpoint: http://localhost:8765
# timeout: 30 (秒)
```

代码中的默认值（`OpenClawGateway::initialize()`）：
```cpp
bool initialize(
    const std::string& bridgeEndpoint = "http://localhost:8765",
    int timeoutSeconds = 30
);
```

## GPT-SoVITS 对接

### 概述

GPT-SoVITS 是一个独立部署的语音合成服务，Yachiyo 通过 HTTP API 与之交互。
**当前项目中保留了 GPT-SoVITS 对接代码，但暂时不需要启用。**

### 架构

```
┌──────────────┐    HTTP POST     ┌──────────────────┐
│  C++ 后端    │ ── TTSRequest →  │ GPT-SoVITS Server │
│ (Yachiyo)    │ ← TTSResponse ── │    (:5000)        │
└──────────────┘                  └──────────────────┘
```

### 部署 GPT-SoVITS

1. **安装 GPT-SoVITS**（参考 [GPT-SoVITS GitHub](https://github.com/RVC-Boss/GPT-SoVITS)）

2. **启动 API 服务**：
   ```bash
   # GPU 模式
   python api.py --port 5000 --device cuda
   
   # CPU 模式（延迟更高）
   python api.py --port 5000 --device cpu
   ```

3. **配置 Yachiyo**（`config/config.yaml`）：
   ```yaml
   ai:
     gpt_sovits:
       enabled: true
       endpoint: "http://localhost:5000"
       mode: "gpu"                    # "gpu" (timeout=15s) 或 "cpu" (timeout=60s)
       timeout_seconds: 15            # 根据 mode 调整
       voice_presets:
         default: "yachiyou_default"  # 温暖声线
         playful: "yachiyou_playful"  # 调皮声线
         cool: "yachiyou_cool"        # 冷淡声线
   ```

### 请求/响应格式

**TTSRequest**:
```json
{
    "requestId": "uuid",
    "text": "你好世界",
    "language": "zh",
    "voiceId": "yachiyou_default",
    "speed": 1.0,
    "pitch": 0.0,
    "volume": 1.0,
    "emotion": "happy",
    "referenceAudioPath": ""
}
```

**TTSResponse**:
```json
{
    "requestId": "uuid",
    "success": true,
    "audioUrl": "http://localhost:5000/audio/xxx.wav",
    "audioBase64": "base64-encoded-audio",
    "durationMs": 2500,
    "sampleRate": 22050,
    "format": "wav",
    "error": ""
}
```

### 相关代码

| 文件 | 说明 |
|------|------|
| `include/services/GPTSoVITSService.hpp` | TTS 服务接口 |
| `src/services/GPTSoVITSService.cpp` | TTS 服务实现 |
| `include/dto/TTSServiceDTO.hpp` | TTS 请求/响应 DTO |

### 声音预设与情感映射

GPTSoVITSService 内置了情感到声音参数的映射：
- `happy` → 语速 +10%，音调 +0.2
- `sad` → 语速 -10%，音调 -0.3
- `angry` → 语速 +20%，音调 +0.5
- `calm` → 默认参数

## API Key 配置说明

所有 API Key 统一在 `backend/config/config.yaml` 中配置。

### 必需的 API Key

| 服务 | 配置路径 | 获取方式 |
|------|----------|----------|
| DeepSeek Chat | `ai.deepseek.api_key` | [DeepSeek Platform](https://platform.deepseek.com) |
| DeepSeek 审核 | `ai.deepseek_moderation.api_key` | 同上（复用同一 Key） |
| JWT 签名密钥 | `jwt.secret` | 自行生成随机字符串 |

### 可选的 API Key

| 服务 | 配置路径 | 获取方式 | 说明 |
|------|----------|----------|------|
| OpenAI | `ai.openai.api_key` | [OpenAI Platform](https://platform.openai.com) | 备用 AI 引擎 |
| 千问 (阿里云) | `ai.qianwen.api_key` | [DashScope 控制台](https://dashscope.aliyun.com) | 国内替代 |
| Qwen 国际版 | `ai.qwen_intl.api_key` | 同上 | 国际版端点 |
| 百度翻译 APPID | `ai.translation.engines[0].appid` | [百度翻译开放平台](https://fanyi-api.baidu.com/) | 翻译引擎 |
| 百度翻译密钥 | `ai.translation.engines[0].api_key` | 同上 | 翻译引擎 |

### 不需要 API Key 的服务

| 服务 | 说明 |
|------|------|
| OpenClaw | 密钥由 OpenClaw 服务端管理，桥接服务无需 Key |
| GPT-SoVITS | 本地部署，无需 Key |
| Ollama | 本地部署，无需 Key |
| PostgreSQL | 通过 `database.username` / `database.password` 配置 |
| Redis | 通过 `redis.password` 配置（可为空） |

### 安全建议

1. **生产环境**：使用环境变量覆盖 `config.yaml` 中的值：
   ```bash
   export JWT_SECRET_KEY="your-strong-random-secret"
   export DEEPSEEK_API_KEY="sk-..."
   export BAIDU_TRANSLATE_APPID="..."
   export BAIDU_TRANSLATE_API_KEY="..."
   ```

2. **不要将 API Key 提交到 Git**：
   - `config/config.yaml` 中的 Key 字段留空
   - 使用 `.env` 文件或环境变量注入

3. **Docker 部署**：通过 `docker-compose.yml` 的 `environment` 段落注入：
   ```yaml
   services:
     backend:
       environment:
         - JWT_SECRET_KEY=${JWT_SECRET_KEY}
         - DEEPSEEK_API_KEY=${DEEPSEEK_API_KEY}
   ```

## 翻译服务对接

### 支持的引擎

1. **百度翻译 API** — 需要 APPID 和密钥
2. **DeepSeek 翻译** — 复用 DeepSeek API Key，通过 LLM 翻译

### 自动降级

翻译服务支持引擎自动降级：
- 优先使用百度翻译（延迟低、费用低）
- 百度不可用时回退到 DeepSeek（LLM 翻译）
- 所有引擎不可用时返回原文

### 配置

```yaml
ai:
  translation:
    enabled: true
    engines:
      - name: "baidu"
        enabled: true
        appid: ""        # 填入百度翻译 APPID
        api_key: ""      # 填入百度翻译密钥
      - name: "deepseek"
        enabled: true
        api_key: ""      # 复用 DeepSeek API Key
    cache:
      enabled: true
      ttl_seconds: 3600
```

## 内容审核对接

### DeepSeek 内容审核

使用 DeepSeek Chat API 进行内容审核（内置规则 + LLM 判断）。

### 配置

```yaml
ai:
  deepseek_moderation:
    enabled: true
    api_key: ""           # 填入 DeepSeek API Key
    categories:
      - violence
      - adult
      - harassment
      - spam
      - hate
      - profanity
```

### 审核流程

1. **规则审核** — 本地关键词/正则匹配（无 API 调用）
2. **LLM 审核** — 规则通过后调用 DeepSeek 进行语义级审核
3. **缓存** — 相同内容的审核结果缓存 1 小时

## 完整服务编排

所有外部服务通过 `AvatarResponseService` 编排为一条完整管线：

```
用户消息
   │
   ▼
[1. 内容审核] ──→ 违规 → 拒绝
   │ 通过
   ▼
[2. OpenClaw 网关] ──→ 生成文本 + 情感 + 动作
   │
   ▼
[3. 翻译服务] ──→ 翻译为目标语言
   │
   ▼
[4. GPT-SoVITS TTS] ──→ 合成语音
   │
   ▼
[5. Live2D 动画] ──→ 生成动画命令
   │
   ▼
[6. 组装响应] ──→ 返回给前端
```

各步骤均独立容错：任一外部服务不可用时，管线仍能返回部分结果（例如只有文本没有语音）。
